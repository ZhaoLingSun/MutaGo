## 1. 项目基线与不可越界事项

### 1.1 上游与项目身份

- **FROZEN**：MutaGo 基于 KataGo stable v1.16.5，固定提交为 `ba938676d7f42d70950b3a535af2466fb642008c`。必须保留上游历史、目录结构、许可证、贡献者记录和实际分发内容所需的 vendored notices。
- **FROZEN**：MutaGo 是独立项目，不得暗示 KataGo 上游作者、维护者或社区对 MutaGo、Collapse Go 或其模型提供背书。
- **FROZEN**：公共规则身份的形式为 `rulesetId + semanticVersion + SHA-256(canonicalSemanticDescriptorBytes)`。
- **UNFROZEN / unassigned**：公共 `rulesetId` 最终字面值和最终规范语义描述符。
- **AUDIT-BLOCKED / unassigned**：公开 SHA-256；必须在描述符冻结并通过两个独立规范字节实现后才能分配。
- 目录名 `collapse-go` 只是候选 slug，不能作为当前公共 `rulesetId`。

### 1.2 已冻结的规则与架构事实

以下事实不因语义版本含 `draft` 而重新开放：

- C++ 是唯一生产规则、合法性、提子、位置超级劫、settlement、计分、actor、终局和搜索状态权威；Python 是独立慢速 oracle；Node 是薄 Gateway；React 只渲染权威结果。
- JSON 规则事件日志是权威记录，扩展 SGF 只是非权威交换格式。
- 官方 Collapse Go 使用只含黑白占位的 occupancy-only 位置超级劫键（`PositionalSuperkoKey` / PSK），不包含 next actor、特殊标记、配额、phase 或账本。
- 每个已接受、具有稳定后状态的规则事件都把稳定黑白占位追加到 PSK 历史。若行动触发 settlement，先追加行动稳定闭包，再在每个 newest-to-oldest event pop 的稳定闭包后追加；tombstone/no-op 可追加重复项，settlement 重复自动允许，不稳定重建/提子中间态不进入历史。
- 初始空盘是否播种为 PSK 历史第零项仍是明确的 **UNFROZEN** 项，不能从上述规则推导。
- `legalMask` 从精确状态确定性派生并单独输出，不是 `GameState` 字段，也不是神经网络输入。
- 接受结果、接受事件或事件组、完整下一精确状态、下一修订和已提交日志位置组成一个不可拆分的语义提交边界；具体持久化、WAL、ACK 和恢复机制仍未冻结。
- Double continuation 可以是 NORMAL 或 PASS。NORMAL continuation 执行完整落子、提子、自杀/保护和 PSK 合法性事务；PASS continuation 只验证 phase、actor 和 continuation 义务，不执行这些棋盘操作或 PSK 重复拒绝，但仍增加 `A` 与停着连计、提交事件、清除 pending Double、追加未改变的稳定占位并把行动权交给对手。若随后触发 settlement，该对手保存为 `handoffActor`，结算后仍由其行动。

### 1.3 固定动作和模型 ABI

Action Schema V1 的 19×19 kind-major codec 已冻结：

```text
p = 19*Y + X
a = 361*k + p

NORMAL       0..360
IMMORTAL     361..721
DOUBLE_START 722..1082
EIGHTWAY     1083..1443
PASS         1444
```

Model V19、Inputs V9、Training Schema V1 和 Action Schema V1 的规范由[输入特征 ABI V9](./04-输入特征ABI-V9.md)约束。Model V19 标识模型 ABI/图和输出契约，具体权重必须使用独立 checkpoint/model-artifact identity；不得把版本号当作权重身份。

## 3. 实施里程碑

### M1 — 上游集成审计与来源清单

**目标**：在生产代码修改前建立可追溯的 KataGo 集成地图。

审计范围至少包括：

- `cpp/game/board.*`、`boardhistory.*`、`rules.*` 的棋盘、历史、ko、计分、撤销和缓存不变量；
- `cpp/search` 的 typed action、实际 actor、价值符号、图搜索、search key 和状态复制；
- `cpp/neuralnet/nninputs.*`、模型描述符、各 backend、NN cache 和输出后处理；
- `cpp/dataio/trainingwrite.*`、Python 训练读取路径、SGF 读写和现有测试入口；
- Model V19 迁移涉及的 checkpoint tensor、EMA/SWA、optimizer state 和 loader/exporter；
- 许可证、贡献者和 vendored notices 的实际分发边界。

必须产出：

- 上游文件与 MutaGo 扩展点审计表；
- search key、PSK key、NN-cache key 的独立用途和调用图；
- 精确状态、日志位置、undo、缓存和检查点的所有权图；
- Model V19 / Inputs V9 / Training Schema V1 实现触点和迁移清单；
- 来源、许可证和模型工件校验摘要。

**退出条件**：所有 M2/M3 前置 AUDIT-BLOCKED 项都有源码或工件证据；不得用名称相似或形状相同替代逐路径审计。

### M2 — 剩余规则身份、状态与 Schema 决策

**目标**：在实现成为事实标准前关闭所有会影响早期规则硬闸门的未决语义，并冻结跨语言契约。

工作项：

1. 决定公共 `rulesetId` 字面值。
2. 冻结最终规范语义描述符字段、规范字节算法、媒体类型和独立测试向量；只有完成后才分配公开 SHA-256。
3. 决定初始空盘是否播种为 PSK 历史第零项，并把决定写入规则规范、描述符和边界夹具。
4. 冻结精确状态的 canonical projection、权威事件语义、accepted event group、状态修订与日志位置的关联。
5. 冻结命令/结果、事件、快照、检查点、派生 legal-mask 读模型和错误类别的字段级 Schema；`legalMask` 仍是派生物，不得移入 `GameState`。
6. 冻结死子分歧恢复的 actor、PASS 状态、提案轮次和线级状态机。
7. 冻结扩展 SGF 属性及明确损失模型；不得以“全部无损”作为未审计默认值。
8. 明确 Action Schema V1 在 JSON 中的 envelope 和坐标表示，但不得改变冻结的 1445 ID codec。
9. 冻结 GATE-RULE-1M 的采样 manifest 格式、分层下限、种子记录和候选描述符绑定方式。

语义提交边界本身已经冻结；数据库、WAL、ACK、快照频率等物理持久化设计可以在 M6 实现前完成，不要求在 M2 选择某一产品。

**退出条件**：C++、Python 和 TypeScript 能对同一规范字节、动作、Schema、错误和夹具测试向量达成一致；初始 PSK 播种不再未决；若公共身份条件尚未满足，M3 不得把临时值发布为最终身份。

### M3 — C++ 规则核心与独立 Python oracle

**目标**：分别实现同一冻结语义，暂不接入生产搜索、生产协议或数据 producer。

C++ 规则核心必须实现：

- 官方初始化、阈值、完整配额向量、四种点行动和 PASS；
- Immortal 动态群保护、Eightway 混合连接和去重气；
- NORMAL 与特殊点行动的原子事务、occupancy-only PSK 和完整历史；
- Double start、NORMAL/PASS continuation、同方控制状态和 `A+2<=T`；
- 全局 newest-to-oldest settlement 账本、逐事件能力停用、全盘重建、同步提子、闭包、no-op 和逐稳定状态 PSK 追加；
- post-settlement 行棋、面积计分、死子流程、认输、超时和终局；
- direct test harness 所需的权威事件投影、重放、撤销/重做和派生 legal mask。

Python 必须从规范独立实现相同行为，优先可读、可检查和最小化，不追求生产性能。Python 可以生成参考事件或规范投影，但不得成为生产权威。

**退出条件**：两种实现分别通过核心 UNIT/GOLD/PROP/UNDO/REPLAY 测试，能够从相同稳定状态接受同一候选行动并输出第 06 文档规定的完整差分投影；尚未开始搜索、生产协议或数据生产。

### M4 — GATE-RULE-1M 早期规则差分硬闸门

**目标**：在规则错误扩散到搜索、协议、产品或训练数据前，以独立实现和一百万候选行动建立硬阻断。

必须完成：

- 全部核心黄金规则夹具；
- Action Schema V1 全 1445 ID 双射测试；
- 重放、撤销/重做、检查点和语义提交投影测试；
- ASan、UBSan 和调试不变量；
- 9×9、13×13、19×19，官方 `1/1/1` 及不同完整配额向量的分层；
- NORMAL、IMMORTAL、DOUBLE_START、EIGHTWAY、PASS、NORMAL/PASS continuation、阈值、PSK、settlement、no-op、计分和非法状态覆盖；
- 最后相关修改后至少 `1,000,000` 个合法/非法候选原子行动，C++ 与 Python 零可复现语义差异；
- 差异自动保存、最小化并转为永久回归夹具的流程。

**退出条件**：满足 [GATE-RULE-1M](./06-测试与一致性门槛.md#8-gate-rule-1m早期一百万原子行动规则差分硬闸门)。任何差异修复后必须从零重新计数。

**硬顺序**：M4 通过前，禁止开始 M5 搜索集成、M6 生产协议/Gateway/Web 和 M7 自博弈或训练数据 producer。不得把后期 NN/E2E 门槛与 M4 合并后推迟。

### M5 — 搜索与动作空间集成

**目标**：在规则硬闸门通过后，把冻结状态机接入 KataGo 搜索。

冻结要求：

- Action Schema V1 使用 `a=361*k+p` 的 kind-major 1445 动作；search edge、child arrays、PV 和 analysis 都保存 typed action，不只保存点；
- 精确 legal mask 从精确状态派生；pending Double 只开放 NORMAL/PASS；
- `DOUBLE_START` 与 continuation 是两个 MCTS 决策节点，第一条边后实际 actor 不变；
- settlement 闭包不产生 MCTS 决策节点，触发边直接到达完整 settlement 后稳定状态；
- value、score、ownership、policy 和 Q 使用实际当前玩家视角，禁止按深度奇偶无条件换号；
- search key、PSK key 和 NN-cache key 分别定义、分别失效、分别测试；神经输入相同但 PSK 上下文不同的状态不能合并 search key；
- search state 保存未来相关精确状态、PSK、账本和日志位置，不内嵌完整权威日志，也不以神经输入代替规则状态。

**退出条件**：合成网络和非 NN 搜索测试覆盖 Double 同方节点、NORMAL/PASS continuation、settlement、PSK、转置、cache 和多深度视角，并通过第 06 文档的 SEARCH/ACT/D4 条目。

### M6 — 生产协议、Gateway 与 Web 客户端

**目标**：在规则硬闸门通过后提供最薄、可恢复且不复制规则的产品路径。

工作项：

- C++ JSON 命令、接受/拒绝结果、事件或事件组、快照、派生 legal mask 和分析流；
- 选择并实现持久化、WAL、ACK、快照与崩溃恢复机制，同时保持接受结果、事件组、下一状态和日志位置的语义原子性；
- Node 子进程生命周期、会话、WebSocket、幂等、背压、乱序/断档恢复和 Schema 验证；
- React 棋盘、特殊标记、配额、actor、legal mask、settlement trace、回放和错误展示；
- 扩展 SGF 按冻结的损失 profile 导入导出；
- 重连、崩溃、旧修订、重复消息、恶意客户端和损坏日志端到端测试。

**退出条件**：任何持久化故障都只能恢复到完整语义提交边界；关闭或篡改客户端规则代码不改变服务端裁决；所有显示结果可追溯到 C++ 权威事件或明确标注的非规则分析流。

### M7 — Model V19、Inputs V9、Training Schema V1 与数据 producer

**目标**：在规则硬闸门通过后实现模型和数据通路，但在 GATE-PROD 前不让样本进入正式训练池。

冻结要求来自[输入特征 ABI V9](./04-输入特征ABI-V9.md)：

- Model V19、Inputs V9 的 38 spatial + 67 global、19×19 居中画布；
- Training Schema V1 与 Action Schema V1；
- kind-major 1445 policy/Q 动作布局和独立 Q 输出；
- 每条 score-belief 路径显式读取 G18，即 `input_global[:,18:19]`；
- legal mask 在神经输入之外，由权威状态派生；
- 普通围棋兼容路由、9/13/19 适配和八种 D4；
- 迁移时保留参数、EMA/SWA 和 optimizer state 的精确复制，新参数按 ABI 精确零初始化；
- 无法重建 exact legal mask 的 legacy 数据不得进入 V1 exact-mask training。

实现工作包括模型 loader/exporter、后端、replay writer/reader、shuffler、训练 loss、self-play producer、provenance 和损坏样本拒绝。

**退出条件**：形状、版本、G18、迁移、前向、D4、mask、T0/T1、packing、legacy 兼容、producer/reader round-trip 和损坏样本测试通过。M8 前产生的数据只能隔离为开发数据。

### M8 — GATE-PROD 完整生产者、训练与发行准入

**目标**：执行绑定确切生产者元组的后期完整门槛，同时保留早期规则证书。

必须完成：

- GATE-RULE-1M 证书在最后规则相关修改后仍有效；失效则先完整重跑；
- 公共 `rulesetId`、最终规范描述符和公开 SHA-256 已正式分配并通过独立字节审计；
- 全部规则、日志/Schema、持久化恢复、搜索、NN、D4、SGF、Gateway/Web 和 E2E 测试；
- ASan、UBSan、撤销/重做、完整重放、检查点、PSK、阈值和完整 settlement trace；
- Model V19 / Inputs V9 / Training Schema V1 的迁移、形状、mask、packing 和 producer/reader 验证；
- 准入报告绑定代码提交、规则身份、Schema、模型/checkpoint、producer、编译器、构建、生成器、种子和分层计数；
- release candidate 的许可证、来源、非背书、模型卡、数据来源和已知限制审查。

**退出条件**：满足 [GATE-PROD](./06-测试与一致性门槛.md#9-gate-prod完整生产者训练与发行准入门槛)。M8 前的开发数据不得追认混入正式训练池。

### M9 — 分阶段训练与验证

**目标**：只在通过 GATE-PROD 的生产者上逐步扩大训练复杂度。

建议顺序：

1. 小棋盘和单能力；
2. 能力成对组合；
3. 官方每方 `1/1/1`；
4. 持续保留普通围棋 replay；
5. 对稀有事件使用预登记的分层 bucket 和类型感知探索；
6. 建立 current/history/counter/ordinary-anchor league；
7. 先同步验证，再扩大异步 worker；
8. BF16 为首发基线，FP8 延后。

任何规则、Schema、模型、mask 或 producer 变化都必须评估是否使 M8 失效，并按规则身份和生产者元组分区数据。

**退出条件**：学习曲线、规则回归、普通围棋兼容、稀有事件覆盖、league 稳定性和可重放性达到预先登记的 beta 指标。

### M10 — 稳定 Beta 与社区发布

**目标**：先证明稳定 beta，再考虑社区训练或广泛分发。

发布前必须：

- 固定公共规则身份、Schema 兼容承诺、模型卡、数据来源和已知限制；
- 提供完整许可证、贡献者、vendored notices 和上游来源说明；
- 明确“不代表 KataGo 上游背书”；
- 公开权威 JSON 日志、恢复契约、扩展 SGF 损失模型和兼容文档；
- 通过 release candidate 的 GATE-PROD 和长期 beta 回归。

社区训练或广泛分发只能发生在稳定 beta 之后；M0 不创建 tag 或 release。

主要依赖链为：

```text
                              +-> M6 协议/Web -----+-> M8(GATE-PROD) -> M9 -> M10
                              +-> M7 模型/数据 ----+
```

- M2 可以进行协议与 Schema **设计**；生产协议实现仍必须等到 M4 通过后进入 M6。
- M5、M6、M7 在 M4 后可以按接口依赖部分并行，但三者全部退出后才能进入 M8。
- M7 的 loader、模型代码和 producer 只能在 M4 后实现；M8 前产出的样本仍须隔离。
- M8 是后期完整门槛，不得替代、吞并或推迟 M4 的早期一百万行动规则闸门。

## 5. 精确状态、日志位置与派生 legal mask

### 5.1 精确状态必须保留的语义

无论最终类和字段如何组织，C++ 精确状态必须直接保存或能由权威日志无损恢复：

- 棋盘尺寸、当前黑白占位和 stable stone/source identities；
- 实际下一 actor；
- base-Go 规则、贴目、ko、encore 和计分状态；
- 官方 occupancy-only PSK 的完整精确上下文；
- `T`、`A`、触发计数、PASS 连续数、pre/post phase；
- pending Double owner 和关联事件；
- 初始、剩余和已用配额的精确整数；
- 完整有序特殊事件账本、逻辑时间戳、稳定 ID 和生命周期；
- recent atomic history 和 `LegacyV7View` 所需投影；
- 死子流程、恢复行棋和终局状态中已冻结的语义；
- 已提交权威日志位置或与其一一对应的状态修订。

完整 JSON 日志是独立权威记录，不是 `GameState` 字段。接受结果、事件组、下一状态和日志位置必须一起提交，但这不要求把事件正文复制进状态。

`legalMask` 由 exact-state reducer 单独派生：

```text
legalMask = deriveLegalMask(exactState, ActionSchemaV1)
```

它不是 `GameState` 字段。可以缓存或附在快照/事件结果上，但必须绑定权威修订；缓存方式、存放位置和失效实现为 **UNFROZEN**。

## 8. 决策关闭规则

一个 **UNFROZEN** 或 **AUDIT-BLOCKED** 项只有在以下条件全部满足后才能改为 **FROZEN**：

1. 有明确负责人、作用域和受影响里程碑；
2. 审计项附源码、checkpoint、格式或独立规范字节证据；
3. 提案覆盖正常、边界、非法、损坏和兼容示例；
4. C++、Python、Node/TypeScript、模型和数据边界中所有受影响路径已识别；
5. 有可执行测试向量，并说明对 semantic version、规则哈希、Schema 主版本、producer identity 和门槛证书的影响；
6. 相关设计文档同步更新，不以“代码已经这样写了”代替决策；
7. 若决定影响 GATE-RULE-1M 或 GATE-PROD，明确证书是否失效并安排完整重跑。

修改 **FROZEN** 项时：

- 改变规则语义：新的 semantic version **和**新的规范描述符哈希；
- 改变不兼容线格式：对应 Schema 主版本；
- 改变训练样本语义：新的 producer identity、数据分区并重新评估 GATE-PROD；
- 改变规则 reducer、oracle、PSK、settlement 或动作 codec：GATE-RULE-1M 失效并从零重跑；
- 改变许可证或来源：停止发布，先完成法律与来源审计。

## 9. 主要风险与门禁

| 风险 | 禁止的捷径 | 门禁 |
|---|---|---|
| 浏览器或 Node 复制规则 | 为响应速度本地算提子、PSK、settlement 或终局 | E2E 篡改测试；只接受 C++ 权威状态 |
| Python 与 C++ 同源错误 | 把 C++ 翻译成 Python 或共享合法性代码 | 独立实现审查、黄金夹具和 GATE-RULE-1M |
| 规则错误扩散 | 先做搜索、协议或自博弈，最后再跑差分 | M4 必须位于 M5/M6/M7 之前 |
| 过早发布身份 | 把目录 slug、临时描述符或占位哈希当成公共身份 | M2 独立规范字节测试后才分配 |
| 初始 PSK 被偷偷固定 | 实现默认把空盘加入或不加入历史 | PSK-INIT-01 明确决策、描述符字段和双方案夹具 |
| 丢失稳定 PSK 历史 | 只记录行动终盘或省略 settlement no-op | 每个稳定事件追加、完整重放和差分投影 |
| 记录不一致 | 先写状态再写事件，或反向分两次提交 | 接受结果/事件组/下一状态/日志位置语义原子性和故障注入 |
| legal mask 污染状态域 | 把 mask 当 `GameState` 字段或由客户端补算 | exact-state 派生、修订绑定和 E2E 测试 |
| 键空间混用 | 一个通用 `stateHash` 用于 search、PSK、NN cache | M1 调用图与 M5 三域独立测试 |
| settlement 被简化 | 批量停用能力、跳过 no-op 或记录中间棋盘到 PSK | newest-to-oldest 逐事件轨迹与稳定闭包测试 |
| Double PASS 误走落子逻辑 | 对 PASS continuation 做提子、自杀或 PSK 检查 | CG-DBL-004 专项夹具 |
| SGF 假定无损 | 强行要求所有 JSON 语义 round-trip | 声明损失 profile、损失报告和拒绝测试 |
| 门槛前数据污染 | 开发数据直接加入正式 replay | M8 producer 准入、隔离和 provenance |
| 上游背书误导 | 使用 KataGo 名称暗示官方认可 | 发布文案、许可证和非背书审查 |

## English Summary

MutaGo is pinned to KataGo stable v1.16.5 at `ba938676d7f42d70950b3a535af2466fb642008c`. Collapse Go `0.1.0-draft` gameplay semantics described by the frozen rules are already frozen despite the word `draft`. The public `rulesetId` literal and canonical-descriptor fields/canonicalization remain **UNFROZEN / unassigned**; assignment of the final public descriptor SHA-256 remains **AUDIT-BLOCKED / unassigned**. The `collapse-go` directory name is only a candidate slug.

The roadmap enforces a strict early ordering. After upstream audit and the remaining identity/state/schema decisions, M3 implements the C++ rules core and an independent Python oracle. M4 then runs **GATE-RULE-1M**, including the core golden, replay, undo, sanitizer, and one-million-action differential suite. Search integration, production gameplay protocol, Gateway/Web, model-connected self-play, and training-data production are prohibited until this early gate passes. The later **GATE-PROD** retains a valid early certificate and adds the complete search, protocol, persistence, Model V19, Inputs V9, Training Schema V1, SGF, D4, migration, E2E, provenance, training, and release checks.

Official Collapse Go uses occupancy-only positional superko. Every accepted rule event’s stable post-state is appended; a settlement-triggering action appends its own stable closure first, followed by every newest-to-oldest event pop’s stable closure. Tombstone/no-op repetitions are allowed, and unstable rebuild/capture intermediates are excluded. Whether the initial empty board is seeded as history item zero remains unresolved and must be decided before a final qualifying rule-gate certificate.

Action Schema V1 is fixed and kind-major with `a=361*k+p`: NORMAL `0..360`, IMMORTAL `361..721`, DOUBLE_START `722..1082`, EIGHTWAY `1083..1443`, and PASS `1444`. Model V19, Inputs V9, and Training Schema V1 are also fixed ABI families; Model V19 does not identify concrete weights, which require a separate checkpoint/model-artifact identity.

Exact state contains future-relevant rules data and a committed log position, not the full authoritative event log. `legalMask` is derived from exact state and emitted separately, never stored as a semantic `GameState` field. For every accepted transition, the result, emitted event group, complete next state, next revision, and committed log position form one semantic commit boundary, while concrete persistence, WAL, ACK, snapshot, and crash-recovery mechanics remain unfrozen.

Remaining open items include the public identity, canonical descriptor bytes, initial PSK seeding, exact state ownership, protocol envelopes, physical persistence, dead-stone dispute recovery details, search/NN-cache integration, and the SGF loss model. SGF testing must honor the declared loss profile rather than presume universal losslessness. BF16 is the initial training baseline; deferring FP8 is frozen, while any future FP8 activation and implementation remain a separate decision.
