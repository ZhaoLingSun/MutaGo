## 1. 项目基线与不可越界事项

### 1.1 上游与项目身份

- **FROZEN**：MutaGo 基于 KataGo stable v1.16.5，固定提交为 `ba938676d7f42d70950b3a535af2466fb642008c`。必须保留上游历史、目录结构、许可证、贡献者记录和实际分发内容所需的 vendored notices。
- **FROZEN**：MutaGo 是独立项目，不得暗示 KataGo 上游作者、维护者或社区对 MutaGo、Collapse Go 或其模型提供背书。
- **FROZEN**：公共规则身份三元组为 `mutago.collapse-go` / `0.1.0-draft` / `a21c67d7962b71a3a53b895de824dc6312502362de5341103c0265c2c81d0899`。
- **FROZEN**：摘要输入是 `rfc8785-jcs-ascii-safe-integer-v1` profile 产生的 14973 字节规范 UTF-8 描述符。profile 只约束 JSON 词法、值域与规范字节：ASCII 字符串与键、安全有符号整数 `[-9007199254740991,9007199254740991]`、布尔、`null`、数组和对象；拒绝重复键、浮点、非 ASCII 数据和不安全整数。关闭式 descriptor Schema、描述符不变量和跨制品绑定另行拒绝未知字段或语义错误。独立实现必须复现精确字节和 lowercase SHA-256。
- **FROZEN**：内部 variant enum/ID、目录名 `collapse-go`、运行模式标签、Git SHA 和模型 SHA 均不是公共规则身份，不能代替或改变该三元组。

### 1.2 已冻结的规则与架构事实

以下事实不因语义版本含 `draft` 而重新开放：

- C++ 是唯一生产规则、合法性、提子、位置超级劫、settlement、计分、actor、终局和搜索状态权威；Python 是独立慢速 oracle；Node 是薄 Gateway；React 只渲染权威结果。
- JSON 规则事件日志是权威记录，扩展 SGF 只是非权威交换格式。
- 官方 Collapse Go 使用只含黑白占位的 occupancy-only 位置超级劫键（`PositionalSuperkoKey` / PSK），不包含 next actor、特殊标记、配额、phase 或账本。
- 每个已接受、具有稳定后状态的规则事件都把稳定黑白占位追加到 PSK 历史。若行动触发 settlement，先追加行动稳定闭包，再在每个 newest-to-oldest event pop 的稳定闭包后追加；tombstone/no-op 可追加重复项，settlement 重复自动允许，不稳定重建/提子中间态不进入历史。
- 初始空盘占据固定为 PSK 历史第零项；在任何规则事件前，它是历史中唯一条目。
- `legalMask` 从精确状态确定性派生并单独输出，不是 `GameState` 字段，也不是神经网络输入。
- 接受结果、接受事件或事件组、完整下一精确状态、下一修订和已提交日志位置组成一个不可拆分的语义提交边界；具体持久化、WAL、ACK 和恢复机制仍未冻结。
- Double continuation 可以是 NORMAL 或 PASS。NORMAL continuation 执行完整落子、提子、自杀/保护和 PSK 合法性事务；PASS continuation 只验证 phase、actor 和 continuation 义务，不执行这些棋盘操作或 PSK 重复拒绝，但仍增加 `A` 与停着连计、提交事件、清除 pending Double、追加未改变的稳定占位并把行动权交给对手。若随后触发 settlement，该对手保存为 `handoffActor`，结算后仍由其行动。
- MVP 不启用协商死子移除捷径或死子争议协议；post-settlement 普通行棋持续到两个连续 PASS，随后直接按当前稳定盘面计分。未来协商扩展必须使用新的语义版本、描述符与协议测试。
- 认输和游戏语义超时只在暴露的稳定 `COLLAPSE_PLAY`（含 pending Double）或 `ORDINARY_PLAY` 边界接受。终止若先于候选动作提交则立即终局且无 settlement/计分；动作一旦提交，其触发的完整 settlement 不可中断，运维超时、断线和取消也不得合成游戏 `TIMEOUT`。

### 1.3 固定动作和模型 ABI

Action Schema V1 的 19×19 kind-major codec 已冻结：

```text
p = 19*Y + X
a = 361*k + p

NORMAL       0..360
IMMORTAL     361..721
DOUBLE_START 722..1082
EIGHTWAY     1083..1443
PASS         1444
```

Action V1 的 canonical JSON envelope 只包含 `schemaVersion`、`actionId` 和 `kind`；坐标从 `actionId` 唯一导出，冗余坐标或未知字段必须拒绝。9×9、13×13、19×19 分别以 `(5,5)`、`(3,3)`、`(0,0)` 居中到 19×19 画布，footprint 外点行动非法；D4 围绕 `(9,9)`。

Model V19、Inputs V9、Training Schema V1 和 Action Schema V1 的规范由[输入特征 ABI V9](./04-输入特征ABI-V9.md)约束。Model V19 标识模型 ABI/图和输出契约，具体权重必须使用独立 checkpoint/model-artifact identity；不得把版本号当作权重身份。

### M2 — 剩余精确状态与生产 Schema 决策

**目标**：在实现成为事实标准前，关闭规则核心和后续产品路径仍需的状态所有权、生产事件与恢复合同；M0 已冻结的公开身份、描述符、初始 PSK 和 Action V1 envelope 不再属于未决项。

工作项：

1. 冻结精确状态的 canonical projection，以及它与 M0 `semantic-projection-v1` 测试投影的边界。
2. 冻结生产权威事件语义、accepted event group、状态修订与日志位置的关联。
3. 冻结 M0 之外的命令/结果、生产事件、快照、检查点、派生 legal-mask 读模型和错误类别字段级 Schema；`legalMask` 仍是派生物，不得移入 `GameState`。
4. 决定 settlement 轨迹的生产封装是内嵌步骤还是带共同事务边界的扁平事件。
5. 冻结扩展 SGF 属性及明确损失模型；不得以“全部无损”作为未审计默认值。
6. 冻结 GATE-RULE-1M 的采样 manifest 格式、分层下限、种子记录和公开描述符绑定方式。
7. 保持 MVP 死子捷径与争议协议禁用；未来若提议协商流程，必须作为新语义版本、描述符和状态机项目，不得阻塞或改变当前 MVP。
8. 冻结生产命令层对管理终止的排序表达：只在暴露稳定边界接受；终止先于动作提交立即终局，动作先提交则完整 settlement 不可中断；请求/传输超时与游戏 `TIMEOUT` 分域。

语义提交边界本身已经冻结；数据库、WAL、ACK、快照频率等物理持久化设计可以在 M6 实现前完成，不要求在 M2 选择某一产品。

**退出条件**：C++、Python 和 TypeScript 能消费同一 M0 描述符、Action V1、Schema 与中立向量；规则核心所需精确状态边界和生产协议后续接口不含隐式语义选择；所有未决生产格式都有明确版本化与测试计划。

### M3 — C++ 规则核心与独立 Python oracle

**目标**：分别实现同一冻结语义，暂不接入生产搜索、生产协议或数据 producer。

C++ 规则核心必须实现：

- 官方初始化、阈值、完整配额向量、四种点行动和 PASS；
- Immortal 动态群保护、Eightway 混合连接和去重气；
- NORMAL 与特殊点行动的原子事务、occupancy-only PSK 和完整历史；
- Double start、NORMAL/PASS continuation、同方控制状态和 `A+2<=T`；
- 全局 newest-to-oldest settlement 账本、逐事件能力停用、全盘重建、同步提子、闭包、no-op 和逐稳定状态 PSK 追加；
- post-settlement 普通行棋、两个连续 PASS 后对当前稳定盘面的面积计分、认输、游戏超时和终局；MVP 不实现死子协商移除或争议恢复；管理终止只在暴露稳定边界接受，终止先于动作提交则立即终局，动作先提交则其触发的完整 settlement 不可中断；
- direct test harness 所需的权威事件投影、重放、撤销/重做和派生 legal mask。

Python 必须从规范独立实现相同行为，优先可读、可检查和最小化，不追求生产性能。Python 可以生成参考事件或规范投影，但不得成为生产权威。

**退出条件**：两种实现分别通过核心 UNIT/GOLD/PROP/UNDO/REPLAY 测试，能够从相同稳定状态接受同一候选行动并输出第 06 文档规定的完整差分投影；尚未开始搜索、生产协议或数据生产。

**目标**：在规则错误扩散到搜索、协议、产品或训练数据前，以独立实现和一百万候选行动建立硬阻断。

必须完成：

- Action Schema V1 全 1445 ID 双射测试；
- 重放、撤销/重做、检查点和语义提交投影测试；
- ASan、UBSan 和调试不变量；
- 9×9、13×13、19×19，官方 `1/1/1` 及不同完整配额向量的分层；
- NORMAL、IMMORTAL、DOUBLE_START、EIGHTWAY、PASS、NORMAL/PASS continuation、阈值、PSK、settlement、no-op、计分和非法状态覆盖；
- 最后相关修改后至少 `1,000,000` 个合法/非法候选原子行动，C++ 与 Python 零可复现语义差异；
- 差异自动保存、最小化并转为永久回归夹具的流程。

**退出条件**：满足 [GATE-RULE-1M](./06-测试与一致性门槛.md#8-gate-rule-1m早期一百万原子行动规则差分硬闸门)。任何差异修复后必须从零重新计数。

**硬顺序**：M4 通过前，禁止开始 M5 搜索集成、M6 生产协议/Gateway/Web 和 M7 自博弈或训练数据 producer。不得把后期 NN/E2E 门槛与 M4 合并后推迟。

### M5 — 搜索与动作空间集成

**目标**：在规则硬闸门通过后，把冻结状态机接入 KataGo 搜索。

冻结要求：

- Action Schema V1 使用 `a=361*k+p` 的 kind-major 1445 动作；search edge、child arrays、PV 和 analysis 都保存 typed action，不只保存点；
- 精确 legal mask 从精确状态派生；pending Double 只开放 NORMAL/PASS；
- `DOUBLE_START` 与 continuation 是两个 MCTS 决策节点，第一条边后实际 actor 不变；
- settlement 闭包不产生 MCTS 决策节点，触发边直接到达完整 settlement 后稳定状态；
- value、score、ownership、policy 和 Q 使用实际当前玩家视角，禁止按深度奇偶无条件换号；
- search key、PSK key 和 NN-cache key 分别定义、分别失效、分别测试；神经输入相同但 PSK 上下文不同的状态不能合并 search key；
- search state 保存未来相关精确状态、PSK、账本和日志位置，不内嵌完整权威日志，也不以神经输入代替规则状态。

**退出条件**：合成网络和非 NN 搜索测试覆盖 Double 同方节点、NORMAL/PASS continuation、settlement、PSK、转置、cache 和多深度视角，并通过第 06 文档的 SEARCH/ACT/D4 条目。

### M6 — 生产协议、Gateway 与 Web 客户端

**目标**：在规则硬闸门通过后提供最薄、可恢复且不复制规则的产品路径。

工作项：

- C++ JSON 命令、接受/拒绝结果、事件或事件组、快照、派生 legal mask 和分析流，包括管理终止与动作提交的权威串行顺序；
- 选择并实现持久化、WAL、ACK、快照与崩溃恢复机制，同时保持接受结果、事件组、下一状态和日志位置的语义原子性；
- Node 子进程生命周期、会话、WebSocket、幂等、背压、乱序/断档恢复和 Schema 验证；区分游戏 `TIMEOUT` 与请求/传输超时、取消、断线，禁止合成终局或发布部分 settlement；
- React 棋盘、特殊标记、配额、actor、legal mask、settlement trace、回放和错误展示；
- 扩展 SGF 按冻结的损失 profile 导入导出；
- 重连、崩溃、旧修订、重复消息、恶意客户端和损坏日志端到端测试。

**退出条件**：任何持久化故障都只能恢复到完整语义提交边界；关闭或篡改客户端规则代码不改变服务端裁决；所有显示结果可追溯到 C++ 权威事件或明确标注的非规则分析流。

### M7 — Model V19、Inputs V9、Training Schema V1 与数据 producer

**目标**：在规则硬闸门通过后实现模型和数据通路，但在 GATE-PROD 前不让样本进入正式训练池。

冻结要求来自[输入特征 ABI V9](./04-输入特征ABI-V9.md)：

- Model V19、Inputs V9 的 38 spatial + 67 global、19×19 居中画布；
- Training Schema V1 与 Action Schema V1；
- kind-major 1445 policy/Q 动作布局和独立 Q 输出；
- 每条 score-belief 路径显式读取 G18，即 `input_global[:,18:19]`；
- legal mask 在神经输入之外，由权威状态派生；
- 普通围棋兼容路由、9/13/19 适配和八种 D4；
- 迁移时只精确复制 donor 工件中实际存在、已审计且语义兼容的参数、EMA/SWA、optimizer 与 train state；缺失和新增参数/状态按 ABI 精确零初始化，不得伪造 exact-copy；

## 8. 决策关闭规则

一个 **UNFROZEN** 或 **AUDIT-BLOCKED** 项只有在以下条件全部满足后才能改为 **FROZEN**：

1. 有明确负责人、作用域和受影响里程碑；
2. 审计项附源码、checkpoint、格式或独立规范字节证据；
3. 提案覆盖正常、边界、非法、损坏和兼容示例；
4. C++、Python、Node/TypeScript、模型和数据边界中所有受影响路径已识别；
5. 有可执行测试向量，并说明对 semantic version、规则哈希、Schema 主版本、producer identity 和门槛证书的影响；
6. 相关设计文档同步更新，不以“代码已经这样写了”代替决策；
7. 若决定影响 GATE-RULE-1M 或 GATE-PROD，明确证书是否失效并安排完整重跑。

修改 **FROZEN** 项时：

- 改变规则语义：新的 semantic version **和**新的规范描述符哈希；
- 改变不兼容线格式：对应 Schema 主版本；
- 改变训练样本语义：新的 producer identity、数据分区并重新评估 GATE-PROD；
- 改变规则 reducer、oracle、PSK、settlement 或动作 codec：GATE-RULE-1M 失效并从零重跑；
- 改变许可证或来源：停止发布，先完成法律与来源审计。

## English Summary

MutaGo is pinned to KataGo stable v1.16.5 at `ba938676d7f42d70950b3a535af2466fb642008c`. Collapse Go `0.1.0-draft` gameplay semantics are frozen despite the word `draft`. The public identity is `mutago.collapse-go` / `0.1.0-draft` / descriptor SHA-256 `a21c67d7962b71a3a53b895de824dc6312502362de5341103c0265c2c81d0899`. Internal variant IDs, the `collapse-go` directory slug, runtime labels, Git SHAs, and model SHAs are separate domains.

M0 freezes executable contracts and identity. It provides a 14,973-byte canonical descriptor, five closed Draft 2020-12 source schemas, canonicalization/identity/descriptor/action vectors, contract examples, validation tooling, and minimal C++ Action/RulesetIdentity contract source and tests. The restricted profile governs JSON syntax, value domain, and canonical bytes only; the closed descriptor schema and descriptor checks separately reject unknown fields and semantic violations. `canonicalize`/`hash` enforce only the profile, while descriptor `validate` and repository `check` enforce Schema and applicable invariants. M0 does not implement the full C++ reducer, full independent Python oracle, search, neural integration, training, Gateway, or Web.

The remaining roadmap preserves strict ordering. M1 audits upstream integration; M2 closes exact-state ownership and production-protocol details that M0 intentionally does not define. M3 implements the C++ rules core and an independent Python oracle. M4 then runs **GATE-RULE-1M** before search, production gameplay protocol, Gateway/Web, self-play, or training-data production. The later **GATE-PROD** retains a valid early certificate and adds search, persistence, Model V19, Inputs V9, Training Schema V1, SGF, D4, migration, E2E, provenance, training, and release checks.

Official Collapse Go uses occupancy-only positional superko. Initial empty occupancy is the sole PSK history entry at initialization and has index zero. Every accepted rule event’s stable post-state is appended; settlement appends the triggering action’s stable closure first and then every newest-to-oldest event pop’s stable closure. Tombstone/no-op repetitions are allowed, and unstable intermediates are excluded.

Action Schema V1 is fixed and kind-major with `a=361*k+p`: NORMAL `0..360`, IMMORTAL `361..721`, DOUBLE_START `722..1082`, EIGHTWAY `1083..1443`, and PASS `1444`. The canonical envelope contains `schemaVersion`, `actionId`, and `kind`; coordinates are derived, redundant coordinate fields are rejected, and the 9x9/13x13/19x19 footprints use centered offsets `(5,5)`, `(3,3)`, and `(0,0)`. Model V19, Inputs V9, and Training Schema V1 remain separate fixed ABI families; concrete weights require a separate artifact identity.

Exact state contains future-relevant rules data and a committed log position, not the full authoritative event log. `legalMask` is derived from exact state and emitted separately. The accepted result, event group, complete next state, revision, and log position form one semantic commit boundary, while physical persistence, WAL, ACK, snapshots, and crash recovery remain future implementation choices.

The MVP enables neither agreed dead-stone removal nor a dead-stone dispute protocol. Ordinary play continues until two consecutive passes and then scores the current stable board. Administrative termination is accepted only at exposed stable boundaries: termination-first ends immediately without the candidate action, settlement, or scoring; action-first requires any triggered settlement to complete atomically before a later termination is considered. Operational timeouts, disconnects, and cancellation never synthesize game `TIMEOUT`. Any future negotiation flow requires a new semantic version, descriptor, and protocol tests. Remaining open items include exact-state integration, production envelopes, persistence, physical search/cache keys, the SGF loss model, Model V19 implementation points, checkpoint identity, training extensions/operations, performance parameters, and any future FP8 activation; public identity, canonicalization, initial PSK seeding, Action V1, and the current dead-stone policy are not open.
