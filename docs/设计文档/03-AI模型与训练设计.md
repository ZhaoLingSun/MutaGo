## 2. 权威边界与上游兼容边界

**状态：FROZEN**

1. C++ 是生产环境中规则、合法性、状态转移、搜索、结算、终局和计分的唯一权威。
2. Python 是独立实现的慢速参考与差分预言机。它不得调用 C++ 规则实现来伪造“一致”，也不得以逐行翻译替代独立实现。
3. Node 网关只负责进程、会话、WebSocket 和 Schema 编排，不计算合法性、提子、连接、PSK、结算、当前行动者或终局。
4. React + TypeScript 客户端只渲染权威状态，不计算或修正任何规则结果。
5. JSON 事件日志是权威记录和确定性重放来源；扩展 SGF 仅用于交换，不得反向成为训练或规则事实来源。
6. 神经网络只提供先验和预测。合法动作、规则状态、结算轨迹以及最终结果始终来自 C++ 环境。
7. 本项目基于官方 KataGo stable `v1.16.5` 快照开发，但不代表、暗示或声称获得 KataGo 上游认可。许可证、贡献者记录、vendored notices、源码布局和完整历史必须保留。

上游快照当前仍以 Model V16 / Inputs V7 为主要实现边界，可参见 [`modelversion.h`](../../cpp/neuralnet/modelversion.h)、[`nninputs.h`](../../cpp/neuralnet/nninputs.h) 和存档的 [`KataGo README`](../upstream/KataGo-README-v1.16.5.md)。MutaGo **Model V19** 与 **Inputs V9** 是冻结的目标模型 ABI/图和输入契约；Model V18 保留且未发布。Model V19 不标识某一组具体权重，具体权重必须由独立 checkpoint/model-artifact 身份标识。上述设计不声称已被未修改的上游加载器支持，也不暗示当前仓库已经完成实现。

## 3. AI 可见的规则状态

**状态：FROZEN**

AI 不得自行实现下列规则，但搜索状态、动作掩码、训练记录和缓存边界必须能区分其影响：

- 正式 `0.1.0-draft` 对局为空棋盘 19×19、分先、黑先、白贴目 7.5、数子法、中国面积计分、位置超级劫；9×9 与 13×13 为实验棋盘，授子延后。版本名中的 `draft` 不表示这些已列玩法语义仍可由实现自行改写。
- 阈值为

  \[
  T(N)=\left\lfloor\frac{150N^2+180}{361}\right\rfloor,
  \]

  因而 `T9=34`、`T13=70`、`T19=150`。每个完成的原子玩家动作都使全局动作计数加一；PASS 和 Double continuation 都各自计数。
- 官方配额为每方 Immortal、Double-Move、Eightway 各一次，即完整配额向量 `1-1-1`。普通围棋条件使用 `0-0-0`。只有完整语义描述符不同才产生不同公共身份；任何与官方 `1-1-1` 不同的完整配额向量都必须使用不同描述符和哈希，不能仅因运行模式名为“experimental”而改变身份。
- `DOUBLE_START` 是一次带标记放置，随后同一方恰好再获得一次仅允许 `NORMAL` 或 `PASS` 的 continuation。start 和 continuation 都是独立原子动作、搜索节点和训练行；每一步按其真实动作种类执行规则事务。`NORMAL` continuation 执行完整落子、提子、自杀/保护与 PSK 合法性事务；`PASS` continuation 只验证 phase、actor 和续着义务，不落子、不提子、不检查自杀，也不执行 PSK 重复拒绝，但仍增加 `A` 与停着连计、产生事件、清除 pending Double、追加未改变的稳定占据，并在完整提交后把行动权交给对手；若触发 settlement，该对手保存为 `handoffActor`，结算后仍由其行动。
- `DOUBLE_START` 仅在 `A+2<=T` 时合法。当 `A=T-2` 时，start 与 continuation 分别完成第 `T-1`、`T` 个动作；当 `A=T-1` 时禁止开始 Double。触发结算的第 `T` 个动作必须先完整达到稳定闭包，再进入结算。
- 动作数到达 `T`，或在 `T` 之前出现连续两次 PASS，都会触发结算。结算不是玩家选择，不产生 MCTS 决策节点。
- 结算后只允许普通围棋动作；结算会清空 PASS 连续计数，随后仍需新的连续两次 PASS 才结束普通围棋阶段。认输或超时立即判负，不执行结算或计分。
- 官方 Collapse Go 使用只含黑白占据、且不含下一手玩家的 occupancy-only PSK。每个已接受原子动作，包括 `PASS`，都在事件完成后把稳定黑白占据追加到 PSK 历史。点动作在提交前执行 PSK 重复拒绝检查；`PASS` 不改变棋盘，并豁免该重复拒绝检查，但不豁免历史追加。PSK 不包含行动者、特殊标记、配额、动作号或阶段。
- 结算按完整特殊事件账本从全局最新到最旧逐项处理。每项只停用相应能力并重建到确定性稳定闭包，不回滚已经发生的落子或事件。**每个事件（包括棋盘变换为 no-op 的 tombstone）处理后的稳定黑白占据都进入 PSK 历史**；结算生成的重复占据自动允许，但会约束之后的玩家动作。重建、连接重算和提子过程中的不稳定中间棋盘不进入 PSK 历史。

上述规则状态必须由环境显式提供。搜索不得依赖深度奇偶、棋子外观、客户端标记或网络预测来推断当前行动者、continuation 阶段或结算状态。

## 4. 版本身份与不可混用的标识

**状态：FROZEN（版本号、身份分域与不可混用原则）；UNFROZEN（公共 `rulesetId` 字面值、descriptor 字段与规范化）；AUDIT-BLOCKED（公开 SHA-256 的最终分配）**

| 标识 | 冻结值或当前状态 | 用途 |
|---|---|---|
| 公共规则身份构成 | `rulesetId + semanticVersion + SHA-256(canonicalSemanticDescriptor)` | 对外不可变地标识规则语义 |
| `rulesetId` | `unassigned`；目录 slug `collapse-go` 只是候选，不是已分配公共字面值 | 公共规则族标识 |
| canonical descriptor | 字段、编码与规范化为 **UNFROZEN / unassigned** | 完整语义描述制品 |
| 公开描述符 SHA-256 | **AUDIT-BLOCKED / unassigned**；摘要算法及输入关系 `SHA-256(canonicalSemanticDescriptorBytes)` 已冻结 | 最终规范字节的公开摘要 |
| 规则语义版本 | `0.1.0-draft` | 标识当前已经冻结的 Collapse Go 玩法语义版本 |
| Model | `V19` | 标识 MutaGo 模型 ABI、模型图和输出角色契约；**不标识具体权重** |
| Checkpoint / model artifact | 独立工件身份，必须能唯一指向具体权重与训练谱系 | 标识某个可加载权重工件 |
| Inputs | `V9` | 标识神经网络输入特征 ABI |
| Action Schema | `V1` | 标识 kind-major 1445 动作编解码契约 |
| Training Schema | `V1` | 标识训练行、张量、掩码与回放 manifest 契约 |

`rulesetId` 的最终字符串、canonical semantic descriptor 的字段集合与规范化算法为 **UNFROZEN**。公开 SHA-256 当前为 `unassigned`；只有描述符冻结并通过独立审计后才可分配，因此“最终哈希分配”仍为 **AUDIT-BLOCKED**。在此之前不得把目录名提升为公共 ID，不得发布占位哈希、创建正式规则标签或宣称公共规则身份已经稳定。

Model V19 只回答“这个工件遵循哪一种 ABI/图”；它不能代替 checkpoint/model-artifact ID。模型、数据集、检查点、评测结果和自博弈批次必须同时记录规则身份状态、代码提交、Model/Inputs/Action/Training 版本、具体模型工件身份以及模型谱系。任何一个兼容性字段不同，都不得静默拼接、缓存复用或混入同一训练池。

## 5. 状态、事件与键空间

**状态：FROZEN（状态分域、键语义与精确 keying 要求）；UNFROZEN（物理布局、哈希实现以及 raw/postprocessed 缓存层选择）**

### 5.1 权威状态、事件日志与派生输出

C++ `GameState` 只保留决定未来规则转移所需的精确状态：可见棋盘与稳定 source identity、实际下一行动者、普通/Double continuation 控制状态、双方初始/剩余/已用配额、`A`/`T`/PASS 连续计数、pre/post-settlement 阶段、精确 occupancy-only PSK 上下文、完整有序特殊事件账本及其稳定 ID/时间戳/处置状态、近期原子动作记录、base-Go 兼容状态和终局状态。具体 C++ 类型布局不由本文冻结。

完整 JSON 事件日志是独立的权威记录与确定性重放来源，**不得为了搜索方便把整条事件序列塞入 `GameState`**。`GameState` 只需保存与当前状态关联的日志 revision/cursor 或等价位置，以及未来规则仍会读取的账本状态。

长度 1445 的合法掩码由权威 reducer/legality 路径从精确状态派生并单独输出；它不是 `GameState` 的持久语义字段，也不是神经输入。实现若缓存合法掩码，必须把它绑定到精确权威状态 revision 或语义等价键，状态变化后不得沿用旧掩码。

搜索的每条玩家动作边对应一个原子动作。结算可以在该动作之后产生多个有序内部轨迹步骤，但这些步骤不是玩家动作，也不是 MCTS 子节点。

### 5.2 键空间必须分离

| 键或身份 | 必须表达的语义 | 明确不得等同于 |
|---|---|---|
| 公共规则身份 | 公开规则语义；当前未分配字段保持 `unassigned` | 任一局面哈希、模型哈希或目录 slug |
| `PositionalSuperkoKey`（PSK） | **仅黑白占据** | 行动者、特殊标记、配额、动作号、阶段或搜索键 |
| 搜索/transposition key | 所有会改变未来合法转移、行动者、阶段、终局或价值解释的状态，包括精确 PSK context、typed-action 控制状态、账本和 NN 求值所用历史 | 仅占据的 PSK 键、NN 输入哈希或派生 legal mask |
| Raw NN cache key | 具体 model/checkpoint identity、descriptor/Inputs ABI、精确规范输入 bytes（或带 full-byte equality verification 的 digest）、metadata、兼容适配器、内部 symmetry 与 precision 选项 | 搜索键、公共规则哈希或 PSK 键 |
| Postprocessed/masked NN cache key | Raw key 的全部内容，再加精确 1445-bit legal-mask digest、全部 policy 后处理参数和 search-only suppression 选项 | 只按网络输入命中的 raw key |
| 稳定事件 ID / 日志位置 | 事件日志中的唯一顺序、审计身份和当前状态位置 | 棋盘坐标、动作索引、临时内存地址或完整事件日志本身 |

搜索键必须区分同一占据但行动者、Double continuation、配额、动作计数、PASS 连续计数、结算阶段、事件账本或可达 PSK 历史不同的状态。PSK 的语义字段已经冻结为 occupancy-only；PSK 的字节编码、哈希宽度、碰撞处理和存储布局仍为 **UNFROZEN**。无论采用何种物理编码，“未来转移不等价则不得复用”都是冻结不变量。

缓存 raw outputs 还是已经合法掩码/归一化的结果是实现层选择，而不是 ABI 强制：

- raw cache hit 必须针对当前状态重新计算并应用权威合法掩码；
- masked/postprocessed cache 只有在 key 精确包含 legal mask 与全部后处理/抑制参数时才可复用；
- 任何层都不得跨越 key 中未表达的规则、checkpoint、输入、合法性或推理差异。

上述 keying 要求由已冻结的 [`04-输入特征ABI-V9.md`](04-输入特征ABI-V9.md) §G 约束。具体缓存层组合、淘汰策略、digest 算法和内存布局为 **UNFROZEN**。

## 6. 固定 19×19 画布与 D4

**状态：FROZEN**

所有支持棋盘都嵌入固定 19×19 画布。画布坐标为零基 `(x,y)`，每轴范围为 `0..18`；局部棋盘点 `(x_N,y_N)` 映射为 `(x_N+offset, y_N+offset)`。

| 棋盘 | offset | 画布有效范围 |
|---|---:|---|
| 9×9 | `(5,5)` | `x,y = 5..13` |
| 13×13 | `(3,3)` | `x,y = 3..15` |
| 19×19 | `(0,0)` | `x,y = 0..18` |

画布外但张量内的格点必须由有效区域掩码清零或排除：

- 不得作为卷积、池化、注意力、策略或辅助头中的真实棋盘点；
- 不得稀释全局平均池化；
- 不得获得合法动作；
- D4 变换后仍必须保持有效区域、特征、动作、合法掩码和目标一致。

八个 D4 变换全部围绕固定画布中心 `(9,9)` 进行。相对位置偏置按 D4 轨道共享或约束；具体轨道表和参数化为 **UNFROZEN**，但不得引入与旋转或镜像方向绑定的未经声明偏差。

## 7. Action Schema V1

**状态：FROZEN**

### 7.1 语义动作与 kind-major 顺序

点动作类型 code 固定为：

| `kind` | 名称 |
|---:|---|
| 0 | `NORMAL` |
| 1 | `IMMORTAL` |
| 2 | `DOUBLE_START` |
| 3 | `EIGHTWAY` |

对于语义 `N×N` 棋盘，必须先使用冻结的居中变换

\[
(X,Y)=C_N(x,y)=\left(x+\frac{19-N}{2},\ y+\frac{19-N}{2}\right)
\]

映射到 19×19 画布，再使用

\[
p=19Y+X,
\qquad
a=361k+p,
\qquad
PASS=1444.
\]

因此 Action Schema V1 在所有受支持棋盘上都固定为 1445 个整数 ID，并按完整动作族依次排布：全部 `NORMAL` 画布点、全部 `IMMORTAL` 画布点、全部 `DOUBLE_START` 画布点、全部 `EIGHTWAY` 画布点，最后是 `PASS=1444`。较小棋盘有效区域外的槽位由 legal mask 禁用。协议可以使用 typed action `{kind,loc}`，但任何 Action Schema V1 整数 ID、日志 ID、训练 ID 或客户端映射都不得定义 `a_N`、`PASS_N` 或其他紧凑替代编号；point-major 的 `4*p+kind` 同样禁止。

### 7.2 固定 19×19 画布动作

网络始终输出 1445 个动作值：

\[
4\times19^2+1=1445.
\]

对固定画布坐标 `(X,Y)`：

\[
p(X,Y)=19Y+X,
\qquad
a(k,X,Y)=361k+p(X,Y),
\qquad
a_{PASS}=1444.
\]

| Action ID range | Meaning |
|---:|---|
| `0..360` | `NORMAL` |
| `361..721` | `IMMORTAL` |
| `722..1082` | `DOUBLE_START` |
| `1083..1443` | `EIGHTWAY` |
| `1444` | `PASS` |

9×9 和 13×13 动作先按冻结 offset 映射到 19×19 画布，再使用上述 kind-major ID；非有效区域的四个点动作族条目全部非法。物理张量可以采用 NCHW、NHWC 或后端专用布局，但导入、导出、缓存和训练记录必须通过 Action Schema V1 显式转换到上述语义顺序，不得把后端内存排列当作未记录的动作 ABI。

### 7.3 精确合法掩码

C++ 环境为每个决策节点从精确权威状态派生并单独输出 `legalMaskNA: bool[B,1445]`。该掩码不属于 38+67 神经输入，也不得作为 `GameState` 的持久语义成员；网络、Python 训练器、Node 和 React 都不得重建或近似它。

掩码至少必须反映：

- 有效棋盘范围、占据、提子、自杀与精确 PSK；
- 特殊配额、动作阈值、当前阶段和特殊动作可用性；
- Double continuation 仅允许 `NORMAL` 或 `PASS`；
- 结算后仅允许 `NORMAL` 或 `PASS`；
- 终局、认输或超时后不存在新的玩家决策节点。

策略 softmax、根噪声、采样和 MCTS 扩展只能作用于合法集合。非法 logit 可以用于诊断，但不得获得访问次数或训练目标概率。

Action Schema V1 必须提供正向编码、逆向解码、D4 变换与往返测试。任何不能无损往返的动作记录都必须拒绝进入训练池。

## 8. Double-Move 的 MCTS 行动者处理

**状态：FROZEN**

Double-Move 使用两个真实的 MCTS 决策节点，而不是一个组合动作：

| 节点 | 当前行动者 | 合法动作 | 动作后的行动者 |
|---|---|---|---|
| 普通决策节点 | `P` | 环境掩码允许的动作 | 通常为对手；选择 `DOUBLE_START` 时仍为 `P` |
| Double continuation | 同一 `P` | 仅 `NORMAL` 或 `PASS` | continuation 完整执行后确定为对手；若触发 settlement，该对手保存为 `handoffActor` 并在结算后继续行动 |
| 结算闭包 | 无玩家决策 | 无 | 由环境确定下一阶段或终局 |

`DOUBLE_START` 和 continuation 分别产生策略目标、合法掩码、访问分布和原子事件。第一条子边之后行动者不变，因此任何按搜索深度奇偶翻转玩家或价值符号的实现都是错误的。

结算在触发动作完整提交后同步执行。结算可输出多个 UI/回放轨迹步骤和辅助训练标签，但不得插入虚假的策略节点、PASS 节点或 MCTS 访问计数。

搜索键、训练记录和遥测必须显式记录行动者与阶段；不得从上一手颜色或节点深度推断。

## 9. 价值视角与回传

**状态：FROZEN**

网络输出采用当前行动者相对视角。叶节点评估只进行一次到 KataGo 白方为正视角的转换。若当前行动者相对标量为 `q_self`，则搜索存储的白方视角值为：

\[
q_{white}=
\begin{cases}
q_{self}, & \text{当前行动者为白方},\\
-q_{self}, & \text{当前行动者为黑方}.
\end{cases}
\]

所有树内统计和回传保持白方为正，不按深度或边数交替翻转。选边时：

- 白方最大化 `Q`；
- 黑方最大化 `-Q`。

这条规则同样适用于 Double continuation，因为两层连续节点可以拥有同一行动者。

策略、胜负、分差分布、所有权、逐动作 Q 和新增辅助目标的张量视角必须逐头遵守 Inputs/Training ABI。任何颜色交换或符号变换只能在约定边界发生一次，不得由调用方各自猜测。精确视角、T0/T1 决策边界以及 policy/Q 分离契约已在 [`04-输入特征ABI-V9.md`](04-输入特征ABI-V9.md) 中冻结。

## 11. 混合 CNN/Transformer 架构

**状态：FROZEN（宏观结构）；UNFROZEN（未列明的层级细节）**

主干采用以下组合：

1. KataGo 风格残差与 nested-bottleneck CNN 主干，负责局部形状、气、连接和提子模式；
2. 周期性插入的全棋盘 Transformer 块，负责特殊锚点、远距离连通、全局动作计数、结算顺序和跨棋盘依赖；
3. KataGo global-pooling bias，向局部计算注入全局统计；
4. 按 D4 轨道参数化的相对位置偏置；
5. 经验性 D4 数据增强和一致性损失；
6. 可选的八对称推理集成。

Transformer 只在有效棋盘 token 上参与注意力；填充 token 必须被掩码。D4 一致性用于度量和约束经验误差，不得被描述为未经验证的严格数学等变性。

模型族固定为：

| 规格 | 主干宽度 C | CNN macro 数 | Transformer 数 | attention 宽度 | heads |
|---|---:|---:|---:|---:|---:|
| Debug | 96 | 4 | 2 | 64 | 4 |
| Base | 256 | 10 | 4 | 128 | 4 |
| Large | 384 | 12 | 5 | 192 | 6 |

CNN macro 的内部 residual/nested-bottleneck 排列、Transformer 的精确插入位置、FFN 宽度、归一化、激活、dropout、相对偏置桶和逐头损失权重均为 **UNFROZEN**。在冻结前必须用 Debug 对照和迁移消融验证，不得从模型名称反向猜测。

八对称推理集成是可选推理模式，必须写入 NN 缓存键和评测记录；不能把单次推理与集成推理结果混为同一模型指标。

**状态：FROZEN DESIGN / NOT YET IMPLEMENTED**

Inputs V9 的规范来源是 [`04-输入特征ABI-V9.md`](04-输入特征ABI-V9.md)。该文档已经完成并冻结以下设计，本文不得将其重新标为 **AUDIT-BLOCKED**：

- 固定 19×19 画布；
- 38 个 spatial 特征 S0–S37；
- 67 个 global 特征 G0–G66；
- 上游 Inputs V7 的 S0–S21 与 G0–G18 保持原索引和规定语义；
- Collapse 扩展使用 S22–S37 与 G19–G66 的精确冻结定义；

Model V19/Inputs V9 的设计冻结不等于实现完成或具体 checkpoint 存在。实现必须通过 04 的 descriptor 校验、普通围棋 step-zero 对照、八种 symmetry、9×9/13×13/19×19 adapter、policy/Q 布局以及 G18 显式依赖测试后，才能声称支持该 ABI。

## 13. 输出头与训练目标

**状态：FROZEN（头的存在与权威边界）；UNFROZEN（新增头的精确编码和权重）**

Model V19 保留 KataGo 的核心输出：

- policy；
- value；
- score belief；
- ownership。

新增以下辅助预测：

- post-settlement occupancy：预测结算闭包后的稳定黑白占据；
- stone survival：预测当前石在目标结算或约定时域后的存活；
- special-event survival：预测已使用特殊事件对应石或锚点在结算后的存活。

新增辅助头只改善表示学习、分析和诊断，绝不参与合法性、提子、结算顺序、终局或计分裁决。其监督标签只能由 C++ 权威事件日志和结算轨迹生成，并在允许进入训练池前由 Python 预言机差分核验。

Policy 与逐动作 Q 是分离产物。Policy 点逻辑布局为 `[B,Hπ,4,19,19]` 并按 Action Schema V1 展平为 `[B,Hπ,1445]`；Q 使用独立的 `[B,Hq,1445]` 张量，不做 softmax，也不接受 policy cross-entropy masking。合法掩码在网络外应用；网络不输出“合法性概率”。

## 14. 迁移来源与逐张量清单

**状态：FROZEN（donor、step-zero 迁移语义与失败关闭原则）；AUDIT-BLOCKED（面向具体工件的 manifest、张量映射和校验值）**

| 目标规格 | donor | 对照 |
|---|---|---|
| Debug | `kata1-b6c96-s175395328-d26788732` | 同时保留完全 scratch 的 Debug control |
| Base | `kata1-b40c256-s10800760064-d2633359377` | 迁移训练 |
| Large | `kata1-b18c384nbt-s9996604416-d4316597426` | 迁移训练 |

每次迁移必须有机器可读、可审阅、逐张量完整的 migration manifest。每个目标参数和训练状态项只能属于一个明确类别：

1. `exact-copy`：名称、形状、所选 donor 来源和语义完全兼容，逐 bit 复制；
2. `slice`：从 donor 的明确轴和范围取得保留部分，manifest 记录轴、范围和理由；
3. `legacy-action-remap`：旧 361 点策略/Q 映射到 `NORMAL` block，旧 PASS 映射到 action `1444`；
4. `zero-init`：所有新增参数、特殊动作 policy/Q 分支以及对应新增 EMA/SWA/optimizer state 精确置零；
5. `descriptor-update`：只更新 Model V19、Inputs V9、Action Schema V1、Training Schema V1 和相关角色描述符，不伪造 checkpoint 身份。

任何缺失、重复分类、形状不符、未消费张量或不明状态都必须使迁移失败。禁止盲目 `strict=False`、按名称猜测、静默忽略 missing/unexpected keys，禁止使用会注入噪声的 channel-expansion utility。

冻结的 step-zero 原则与 [`04-输入特征ABI-V9.md`](04-输入特征ABI-V9.md) §H 一致：

- 保留的 raw-model parameters 逐 bit 复制；新增 parameters 精确为零；
- 旧普通点输出进入 `NORMAL`，旧 PASS 进入 1444；`IMMORTAL`、`DOUBLE_START`、`EIGHTWAY` 的 policy 与 Q 初值精确为零；
- 新输入列和新插入模块的初始贡献为零，普通围棋 legacy route 保持原执行顺序；
- 保留的 EMA/SWA parameters 逐 bit 复制，新增 EMA/SWA parameters 置零，并保留 `n_averaged`；
- 保留参数的 optimizer momentum/moment/state buffers 精确复制，新增参数的 optimizer state 置零；保留 scalar step counters 与 parameter-group hyperparameters；
- 保留全部无关 train state，不随机扰动，也不静默删除 optimizer 或 SWA state。

架构在训练中如何从 step-zero 起点学习非零特殊分支不改变上述迁移契约。具体 donor 文件校验和、模块名、slice 映射和完整 manifest 只有在目标实现与工件存在后才能解除 **AUDIT-BLOCKED**；Model V19 本身不能充当这些工件的身份。

迁移验证至少包括：manifest 覆盖率 100%、保留权重/EMA/SWA/optimizer 校验值、普通动作与 PASS 对照、新参数及状态零值检查、legacy route bitwise 对照、单次前向有限值检查、导出/重载一致性和 Debug scratch 对照。donor 的来源、许可和再分发条件必须在任何社区发布前完成审计。

## 15. Training Schema V1 与样本边界

**状态：FROZEN DESIGN / NOT YET IMPLEMENTED（行语义、强制 manifest/arrays、packing 与 T0/T1）；UNFROZEN（未由 04 指定的容器、压缩和分片实现）**

每个训练行恰好对应一个非终局玩家决策，而不是 UI 帧、终局 policy 行或结算内部步骤。`DOUBLE_START` 与 continuation 分别产生训练行，两行使用同一实际行动者视角；settlement 中间状态不产生训练行。

[`04-输入特征ABI-V9.md`](04-输入特征ABI-V9.md) 已冻结每个 V1 replay shard 的强制 manifest/arrays：

```text
replaySchemaVersion         uint16[1] = [1]
inputVersion                uint16[1] = [9]
actionCodecVersion          uint16[1] = [1]
canvasSize                  uint8[1]  = [19]

binarySpatialChannelIds     uint8[37] = [0..25,27..37]
continuousSpatialChannelIds uint8[1]  = [26]

binarySpatialNCHWPacked     uint8[N,37,46]
continuousSpatialNCHW       float32[N,1,19,19]
globalInputNC               float32[N,67]

legalMaskNTAPacked          uint8[N,2,181]
policyVisitCountsNTA        uint64[N,2,1445]
policyTargetWeightNT        float32[N,2]
```

361 bits 使用 46 bytes 且最后七 bit 为零；1445 bits 使用 181 bytes 且最后三 bit 为零。byte 内 bit order 固定为 big-endian，与 `numpy.unpackbits(..., bitorder="big")` 兼容。加载器只能在相应合法集合上归一化非零 visits。

T0 是当前原子决策：weight 为正、visit sum 为正、mask 非空。T1 是下一条记录的原子决策，使用下一状态自己的 mask；它不是“对手回复”专用目标，在 `DOUBLE_START -> continuation` 间有效。若不存在下一决策，或两个决策状态之间发生 settlement 事务，T1 weight 和 visits 为零，mask 可以全零。

同一次 D4 采样必须一致作用于解包后的 spatial planes、S26、T0/T1 legal masks、visit targets、ownership 及全部 spatial auxiliary targets。global 特征与 scalar metadata 只按 ABI 指定方式处理。历史随机化必须联合清除对应 point、actor 与 kind 字段，不能只丢一个平面。

Replay 在张量外还必须保留或可确定引用：棋盘大小与规则版本、当前为 `unassigned` 的公共规则哈希字段、精确 threshold/quotas、absolute next actor、typed atomic actions、事件 ID/时间戳、Double linkage、账本与 settlement trace/checksum、状态前后哈希、重建 occupancy-only PSK 所需信息、exact masks、source checkpoint/model artifact 和搜索参数。它们属于 replay/审计数据，不要求嵌入 `GameState`。

Shuffler 必须按 manifest 和 profile 分支，拒绝不兼容的 schema version、channel-ID 集合或 action codec。旧 KataGo NPZ 若不能从原始 game/action record、起始状态、完整历史与固定 legality 实现重建精确 mask，就不得进入 V1 exact-mask training；仅把 362-way target 重映射为 1445-way 不充分。

未由 04 固定的容器封装、压缩算法、分片尺寸和存储后端为 **UNFROZEN**，但不得改变上述字段、shape、dtype、bit order、行边界或版本检查。测试随机轨迹、差分失败样本和未通过门禁的自博弈数据必须进入隔离区，不得进入训练池。

## 16. 课程、回放与稀有事件采样

**状态：FROZEN（阶段顺序与必须覆盖的类别）；UNFROZEN（比例和晋级阈值）**

正确性门禁通过后，训练课程按以下方向推进：

1. Debug scratch 与迁移 smoke test；
2. 小棋盘上的单一能力课程；
3. 两两能力组合；
4. 官方 `1-1-1`，逐步覆盖 9×9、13×13 和正式 19×19；
5. 普通围棋 `0-0-0`、官方 Collapse `1-1-1`，以及因完整配额向量或其他规则语义实际不同而具有独立 descriptor/hash 的实验配置混合训练。

回放必须按规则身份、棋盘大小、动作类型、阶段和稀有事件分层。最低限度的稀有桶包括：

- Immortal 零气存活、连接/分裂和被结算撤销；
- Double start、同方 continuation、continuation PASS、动作 `T` 和触发结算；
- Eightway 对角连接、去重气和结算后连接变化；
- PSK 拒绝、PASS 豁免重复拒绝但仍追加稳定占据、结算生成重复；
- 阈值结算、结算前双 PASS、捕获事件 no-op、Double 账本 no-op；
- 结算后普通围棋、重新双 PASS 终局以及人类死子协议分歧后续弈。

稀有桶用于防止高频 `NORMAL` 样本淹没特殊语义。桶定义的精确判定器和采样权重为 **UNFROZEN**，但判定器必须读取 C++ 权威事件，不得从网络输出或 UI 标记推断。

根噪声必须 action-type-aware，只对合法动作施加，并避免四类点动作因分支数量差异而产生未经控制的质量倾斜。具体 Dirichlet 参数、类型间质量分配和随课程变化的调度为 **UNFROZEN**。Double continuation 仍遵循其 `NORMAL/PASS` 合法集合。

## 17. 联赛与模型晋级

**状态：FROZEN（联赛角色）；UNFROZEN（数值门槛）**

联赛至少包含四类参与者：

- `current`：当前候选或最新接受模型；

## 18. 1–4 张 RTX 5090 的 GPU 生命周期

**状态：FROZEN（运行顺序、BF16 基线、FP8 延期决定与发布边界）；UNFROZEN（资源配比以及未来是否、何时、如何启用 FP8）**

3. shuffle 与 Training Schema 校验；
4. Debug 训练；
5. 导出和 C++ 重载；
6. 同步评测与晋级；

### 18.2 异步扩展阶段

同步阶段稳定后，才拆分为持续运行的 C++ self-play、shuffle、训练、导出和 gatekeeper/联赛进程。未验证数据、候选工件、已验证工件、已接受工件和历史工件之间必须具有失败关闭的隔离与原子提升边界。以下名称只是推荐的实现词汇，不是冻结的目录 ABI：

`quarantine -> candidate -> validated -> accepted -> historical/retired`

具体目录名、数据库状态名和持久化布局为 **UNFROZEN**；无论命名如何，未完成验证的工件都不得越级进入 accepted。

检查点必须记录父检查点、donor、migration manifest、代码提交、所有 Schema 版本、规则身份、数据窗口和训练配置。中断恢复不得把部分写入、未知 Schema 或未完成验证的工件提升为 accepted。

1–4 GPU 之间的训练/自博弈/评测配比、batch size、梯度累积、访问数和导出频率为 **UNFROZEN**，应由吞吐、队列积压和评测方差驱动，而不是硬编码为某一机器拓扑。

迁移 checkpoint 必须按 §14 和 04 §H 保存、恢复并验证保留的 optimizer 与 EMA/SWA 状态；新增参数对应状态精确置零。进入后续 MutaGo 训练后，这些状态随具体 checkpoint 保存，并由独立 model-artifact identity 与谱系记录标识，不能仅凭 Model V19 版本号判断是否相同。

### 18.3 发布生命周期

任何模型、检查点、数据集或社区自博弈 worker 都不得在 stable beta 之前公开分发。stable beta 的数值准入条件为 **UNFROZEN**，但至少必须满足本文正确性门禁、长期异步稳定性、规则身份完成、Schema 冻结、普通围棋回归评测和可重复导出。

## 20. 自博弈正确性门禁

**状态：FROZEN**

任何训练数据进入 MutaGo 训练池之前，必须同时满足：

1. 至少 `1,000,000` 次随机合法/非法原子动作尝试；

3. 所有 golden fixtures 通过；

6. D4 等价检查通过；

“零个可复现差异”不是统计容忍度。出现差异后，相关轨迹和派生数据必须留在 quarantine；修复后必须重新完成门禁，不能把失败样本删除后继续累计。

门禁适用于整个 MutaGo 训练池，包括计划保留的普通围棋回放；donor 检查点不是训练数据，但在门禁前只能用于隔离的迁移与前向验证，不得产出可晋级模型。

随机生成器的种子集合、合法/非法比例、各棋盘和规则身份分布、稀有阶段覆盖率及最小化失败样本格式为 **UNFROZEN**，并须在 [06 号测试与一致性门槛](06-测试与一致性门槛.md) 中冻结。无论采样细节如何变化，`>=1,000,000`、零可复现差异及全部列明检查均不可降低。

## 23. 实现不变量摘要

**状态：FROZEN**

1. C++ 决定规则；网络只预测。
2. 每个 MCTS 玩家节点对应一个原子动作；结算没有 MCTS 节点。
3. Double 第一子节点保持同一行动者；行动者永远显式存储。
4. 网络值只在叶节点一次转换为白方为正；回传不按深度翻转。

## English Summary

This document defines the AI, search, and training design for MutaGo’s frozen Collapse Go `0.1.0-draft` gameplay semantics on the pinned KataGo stable `v1.16.5` commit `ba938676d7f42d70950b3a535af2466fb642008c`. It is a design contract, not an implementation claim. [`04-输入特征ABI-V9.md`](04-输入特征ABI-V9.md) is a completed, frozen design for Model V19 / Inputs V9 / Training Schema V1 / Action Schema V1, while the corresponding code, checkpoints, and production pipeline are still not implemented.

C++ is the sole production authority for rules, legality, transitions, settlement, scoring, search, and terminal results. Python is an independent slow differential oracle. Node orchestrates processes, sessions, WebSockets, and schemas, and React renders authoritative state. The full JSON event log remains a separate authoritative record; it is not embedded in `GameState`. A legal mask is derived separately from exact state and is neither a persistent `GameState` field nor a neural input.

The public `rulesetId` literal and canonical-descriptor fields/canonicalization are **UNFROZEN / unassigned**; the final public descriptor SHA-256 is **AUDIT-BLOCKED / unassigned** until the descriptor is frozen and independently audited. The directory slug `collapse-go` is not an assigned public ID. Model V19 identifies the model ABI/graph and output roles, not a concrete set of weights. Every concrete checkpoint or model artifact therefore needs a separate identity and lineage record.

Action Schema V1 is strictly kind-major. For canvas point `p=19*Y+X`, the codec is `a=361*k+p`: `NORMAL` is `0..360`, `IMMORTAL` is `361..721`, `DOUBLE_START` is `722..1082`, `EIGHTWAY` is `1083..1443`, and `PASS` is `1444`. Point-major `4*p+kind` is forbidden. C++ emits the exact `[B,1445]` legal mask separately, and policy normalization, root noise, sampling, and MCTS expansion operate only on legal actions.

Double-Move uses two genuine MCTS decision nodes. After `DOUBLE_START`, the same player acts again with only `NORMAL` or `PASS`; settlement creates no MCTS nodes. A Normal continuation runs the full placement/capture/survival/PSK transaction. A Pass continuation runs none of those board-legality operations but still updates counters, emits an event, clears pending Double, appends unchanged occupancy, and deterministically hands play to the opponent, who remains `handoffActor` if settlement follows. Network values are current-player-relative and are converted exactly once at the leaf to KataGo’s white-positive convention. Tree backup never flips signs by depth: White maximizes `Q`, and Black maximizes `-Q`.

The occupancy-only positional-superko key, search key, NN-cache key, public rules identity, and stable event IDs are distinct. Official Collapse Go PSK contains black/white occupancy only. Every accepted atomic action, including Pass, appends its stable post-state; Pass is exempt only from repetition rejection. Every special-event pop also contributes its stable post-closure occupancy, including no-op tombstones; unstable rebuild/capture intermediates do not. Cache-layer choice is not frozen: raw outputs may be cached and remasked on every hit, or masked/postprocessed results may be cached only when the key includes the exact legal-mask digest and every postprocessing and search-suppression option.

One conditional model covers ordinary Go `0-0-0`, official Collapse Go `1-1-1`, and genuinely different experimental semantic descriptors. The preserved architecture combines a residual/nested-bottleneck CNN trunk, periodic full-board Transformer blocks, D4-orbit relative bias, KataGo global-pooling bias, empirical D4 augmentation/consistency, and an optional eight-way inference ensemble. The fixed families remain Debug `C96 / 4 CNN macros / 2 Transformers / attn64 / 4 heads`, Base `C256 / 10 / 4 / 128 / 4`, and Large `C384 / 12 / 5 / 192 / 6`.

Inputs V9 is exactly 38 spatial channels and 67 global channels. S0–S21 and G0–G18 preserve the defined legacy ABI, Collapse extensions occupy S22–S37 and G19–G66, and every score-belief path explicitly reads G18 through `input_global[:,18:19]`. Policy and per-action Q are separate tensors. Training Schema V1 freezes the replay manifest, packed spatial arrays, `[N,2,1445]` visit targets, `[N,2,181]` legal masks, T0/T1 semantics, bit order, D4 handling, and rejection of legacy rows whose exact masks cannot be reconstructed.

Transfer donors remain `kata1-b6c96-s175395328-d26788732`, `kata1-b40c256-s10800760064-d2633359377`, and `kata1-b18c384nbt-s9996604416-d4316597426`, plus a scratch Debug control. Migration is deterministic and manifest-driven: retained model, EMA/SWA, and optimizer state is copied exactly; new parameters and new state are zeroed; legacy point/PASS outputs map to NORMAL/PASS; special policy and Q branches start at zero; blind `strict=False`, noisy expansion, and silent state loss are forbidden.

Training still progresses from Debug smoke tests through small-board single abilities, ability pairs, official `1-1-1`, and mixed ordinary/Collapse replay, while preserving ordinary-Go anchors, rare-event strata, action-type-aware root noise, and current/history/counter/ordinary-anchor league roles. Synchronous validation precedes asynchronous workers. BF16 is the frozen baseline, and deferring FP8 in this version is frozen; any future FP8 enablement remains unfrozen and requires a new explicit decision. The target lifecycle supports 1–4 RTX 5090 GPUs, and no community model/data distribution is allowed before stable beta.

No training data may enter the MutaGo pool until at least 1,000,000 random legal and illegal atomic-action attempts produce zero reproducible C++/Python differences and all golden fixtures, ASan/UBSan, undo/redo, D4, PSK, threshold, Double-continuation, and complete settlement-trace checks pass. Any reproducible semantic difference fails closed and quarantines the affected traces and derived data.
