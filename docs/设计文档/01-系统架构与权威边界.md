## 1. 架构原则

### 1.1 单一生产权威

**[FROZEN]** C++ 是唯一生产规则与搜索权威。任何会影响合法行动、提子、自杀、混合连接、Immortal 保护、Eightway 气、PSK、阈值、Double 续手、能力结算、行动者、终局或得分的决定，都必须由 C++ 的同一状态机给出。

规范化语义描述符和正式规则文本定义“应当实现什么”；C++ 定义线上“实际接受什么”。两者不一致是阻断发布的缺陷，不能以“运行代码即规范”掩盖，也不能由网关或客户端修补。

### 1.2 独立可验证

**[FROZEN]** Python 规则实现是独立编写的慢速 oracle。它可以牺牲性能换取直接、可解释的算法，但不得调用 C++ 绑定、共享生产 reducer、复制内部哈希或使用同一错误路径作为参考。差分比较规范行动和规范状态，不比较实现私有哈希。

Python 的训练代码是另一个非权威职责：它消费 Training Schema，训练和迁移模型；它同样不拥有在线规则语义。

### 1.3 薄边界层

**[FROZEN]** Node 网关负责进程监督、会话路由、模式校验、持久化编排、WebSocket、认证/限流、取消和背压。它可以拒绝语法不合法的信封，但不得判断语义行动是否合法，也不得推导提子、PSK、结算、当前行动者、死活或终局。

React + TypeScript 客户端只渲染 C++ 权威状态、合法掩码、分析结果和能力结算轨迹。它可以做坐标变换、动画、无状态格式化和“待确认意图”显示，但不得以本地模拟改变权威棋盘。

### 1.4 事件溯源与不可变身份

**[FROZEN]** JSON 事件日志是游戏权威记录。状态快照、缓存、搜索树、WebSocket 消息和 SGF 都可重建或丢弃。扩展 SGF 是交换格式，不是权威恢复源。

公共规则身份的结构为：

`rulesetId + semanticVersion + SHA-256(canonicalSemanticDescriptor)`

在公共身份的组成域中，当前只有语义版本 `0.1.0-draft` 已确定。公共 `rulesetId` 的最终字面值，以及规范语义描述符的字段、编码和规范化方式均为 **[UNFROZEN / unassigned]**；摘要算法及输入关系 `SHA-256(canonicalSemanticDescriptorBytes)` 为 **[FROZEN]**；依赖最终规范字节和独立审计的公开描述符 SHA-256 最终值为 **[AUDIT-BLOCKED / unassigned]**。版本名中的 “draft” 不会重新打开[规则文档](02-坍缩围棋规则-v0.1.0-draft.md)已经列明的冻结玩法语义。`rulesets/collapse-go/` 与 `collapse-go` 只是仓库目录和候选 slug，不得提升为已经分配的公共身份。任何与官方 `1/1/1` 不同的完整配额向量都必须生成不同描述符和规则哈希；语义完全相同的配置不能只因“experimental”标签而获得不同身份。

## 2. 组件与权威矩阵

| 组件 | 拥有的责任 | 明确禁止 |
|---|---|---|
| 规范化规则描述符 | 规则语义、版本参数、身份输入 | 承担运行时状态或模型身份 |
| C++ 规则内核 | `GameState`、合法性、事务、结算、终局、事件、重放 | 接受不匹配规则身份并静默降级 |
| C++ 搜索 | 调用 reducer 扩展节点、应用合法掩码、备份白方为正价值 | 复制或近似规则，按 ply 奇偶决定符号 |
| C++ NN/特征 | 权威特征、掩码应用、模型兼容检查、推理缓存 | 用网络预测替代 PSK 或合法性 |
| Python oracle | 独立慢速语义、黄金向量、差分解释 | 进入线上裁决路径或共享 C++ reducer |
| Python 训练 | Training Schema 消费、损失、迁移、导出 | 修改游戏状态或定义线上合法行动 |
| Node 网关 | 进程、会话、持久化、WebSocket、模式与背压 | 计算提子、行动者、结算、PSK、计分 |
| React 客户端 | 呈现状态/掩码/轨迹，提交意图 | 本地决定合法性、提子、终局或权威状态 |
| JSON 事件存储 | 原样保存 C++ 接受事件并支持恢复 | 修复、补写或解释规则结果 |
| 扩展 SGF | 导入/导出的互换表示 | 作为权威日志、哈希输入或无损保证的默认来源 |

## 3. 与 KataGo 基线的接缝

MutaGo 保留现有源码布局，但不能把 Collapse Go 描述成一个只改 `Rules` 枚举的小插件：

- 上游 [`Board`](../../cpp/game/board.h) 是高性能棋盘、链和简单劫底层；它不强制轮次，完整普通围棋合法性在 [`BoardHistory`](../../cpp/game/boardhistory.h)。Collapse Go 必须有更高层、不可拆分的 `GameState`。
- 上游搜索线程当前分开持有行动者、`Board` 和 `BoardHistory`，见 [`search.h`](../../cpp/search/search.h)。MutaGo 搜索必须把这些未来相关状态统一交给 reducer，不能继续在搜索代码中自行交换行动者。
- 上游 [`GraphHash`](../../cpp/game/graphhash.h) 明确不是复杂全历史的精确身份。它不能直接充当 Collapse Go 的 PSK 或完整搜索键。
- 上游 NN 策略空间是每点一个普通行动加 `PASS`；目标 1445 行动和 Model V19/Inputs V9 是新 ABI，不是把棋盘最大边长设为 19 即自动得到。参见 [`nninputs.h`](../../cpp/neuralnet/nninputs.h) 与 [`modelversion.h`](../../cpp/neuralnet/modelversion.h)。
- 上游 Python [`board.py`](../../python/katago/game/board.py) 明确不实现超级劫，不能直接宣称为差分 oracle。
- 上游[分析引擎协议](../Analysis_Engine.md)是调用方提供局面的异步分析接口，不是 MutaGo 的权威会话和事件溯源协议。

这些说明只识别改造边界，不在首提交中修改上述源码。

## 4. 权威状态：`GameState`

### 4.1 聚合边界

**[FROZEN]** `GameState` 是生产规则与搜索使用的不可拆分聚合体。概念上至少包含：

| 状态域 | 必需内容 |
|---|---|
| 规则身份 | 语义版本 `0.1.0-draft`、公共 `rulesetId`/描述符/哈希的显式未分配状态，以及已解析且不可变的规则参数；正式分配后再绑定完整公共身份 |
| 棋盘占据 | 每个有效点的黑/白/空；PSK 只投影此域 |
| 棋子来源与标记 | 当前占据棋子对应的稳定落子来源，以及存活 Immortal/Eightway/Double 标记 |
| 行动者与阶段 | 当前玩家、特殊阶段、Double 强制续手、结算后普通阶段、终局阶段 |
| 时间状态 | 全局原子行动数、连续停着数、触发原因 |
| 配额 | 每方三种能力的未用/已用状态 |
| Double 上下文 | 起手事件、同一行动者、允许的续手集合 |
| 特殊事件账本 | 双方所有已使用能力的稳定全序、种类、所有者、锚点来源和是否仍在盘上 |
| PSK 上下文 | 从开局到当前、跨能力结算和普通阶段的完整占据历史或等价精确表示 |
| 终局状态 | 进行中、死子协商、计分、认输、超时、胜者和白减黑得分 |

稳定棋子来源或等价机制是必需的：某个特殊棋子被提后，同一点后来出现的新棋子不得“继承”旧锚点能力。精确内存布局为 **[UNFROZEN]**。

### 4.2 概念阶段

序列化枚举名尚未冻结，但状态机必须表达以下语义：

1. **能力阶段**：三种能力按配额和时间窗开放；
2. **Double 续手阶段**：起手已经提交，同一玩家只可 `NORMAL/PASS`；
3. **能力结算**：reducer 内部的确定性闭包，不接受玩家命令；
4. **普通阶段**：所有特殊能力和未用配额失效，只执行普通围棋；
5. **死子协商/恢复对局**：人类流程可以捷径计分，有争议则回到普通对局；
6. **终局**：计分、认输或超时后不可再提交游戏行动。

能力结算可以不作为对外可停留状态，但必须在事件轨迹中完整表示。

## 5. 唯一转换器：`VariantReducer`

### 5.1 概念契约

**[FROZEN]** 所有生产转换都满足以下概念接口；这不是冻结的 C++ 函数签名：

```text
reduce(GameState, Command)
  -> Rejected { reason, unchangedState }
   | Committed { nextState, authoritativeEvent, optionalSettlementTrace }
```

`VariantReducer` 同时负责：

- 从同一状态生成合法行动集合和固定 1445 位掩码；
- 处理落子、`PASS`、认输、超时和终局协商命令；
- 触发并完成能力结算闭包；
- 产生事件、状态投影、终局和搜索所需信息；
- 重放日志并验证记录结果；
- 为 PSK、搜索和 NN 提供不同键投影。

拒绝结果必须保持棋盘、来源、配额、计数、行动者、阶段、账本、PSK、事件序列、终局和所有可见摘要不变。任何先修改再“尽量恢复”的路径必须由测试证明强事务等价。

### 5.2 混合连接、气与保护

**[FROZEN]** 对同色棋子构造无向连接图：

- 所有 N4 相邻同色棋子连接；
- 对 N8 范围内的同色端点，只要任一端是存活 Eightway 锚点，就增加无向连接；
- 对角肩位是否被异色占据不影响该边；
- 异色棋子永不因 Eightway 连接；
- 普通棋子的气接口为 N4 空点，存活 Eightway 锚点的气接口为 N8 空点；
- 一个组的气是所有成员接口的去重空点并集，占据点从不计气。

一个组只要含有至少一个存活 Immortal 锚点即受保护。保护随着当前混合连接动态变化：普通棋子可接入受保护组，保护可经存活 Eightway 边传播；组分裂后，仅包含存活 Immortal 的分量保留保护。受保护零气组可以持续存在，Immortal 也可落入普通规则下的真眼并破坏普通双眼生命。

### 5.3 落子强事务

**[FROZEN]** `NORMAL`、`IMMORTAL`、`DOUBLE_START`、`EIGHTWAY` 共用以下规范顺序：

1. 验证会话状态、行动者、阶段、点位、占据、时间窗和配额等前置条件；
2. 在候选状态放置新棋子并绑定稳定来源；特殊行动在候选状态激活对应锚点或 Double 标记；
3. 重建整盘混合组、去重气和 Immortal 保护；
4. 同时删除每个对方零气且未受保护的组；
5. 重建整盘；
6. 要求新落子所属己方组至少有一口气，或由存活 Immortal 保护；
7. 对最终黑白占据执行位置超级劫检查；
8. 全部通过后，原子提交棋盘、来源、配额、账本、行动计数、停着状态、行动者/阶段和事件。

只有合法特殊落子提交才永久消耗配额。“立即消耗”指 Double 起手事务提交点，不是收到请求时；非法尝试不计行动、不消耗配额、不写日志。

普通落子或任意特殊落子会中断“连续 `PASS`”。特殊标记不是 PSK 占据的一部分，也不能使相同黑白盘面逃过 PSK。

### 5.4 `PASS` 与 Double

**[FROZEN]** `PASS` 是原子行动并增加全局行动数，但免于 PSK 拒绝。其稳定占据仍保留在事件历史中；重复占据不影响停着合法性。

合法 `DOUBLE_START`：

- 先完整执行一次特殊落子事务；
- 立即消耗本方 Double 配额；
- 提交带稳定审计来源的 Double 标记；
- 行动者保持不变并进入强制续手阶段；
- 下一决策恰好只允许 `NORMAL` 或 `PASS`，不得再使用特殊能力；
- `NORMAL` continuation 独立执行完整落子、提子、自杀/保护及 PSK 合法性事务；
- `PASS` continuation 只验证 phase、actor 和 continuation 义务；它不落子、不提子、不检查自杀，也不执行 PSK 重复拒绝，但仍增加全局行动数与停着连计、产生动作事件、清除 pending Double，并把未改变的稳定占据追加到 PSK 历史；
- 任一合法 continuation 完整提交后，下一行动者确定为该 continuation 行动者的对手；若 continuation 触发 settlement，则该对手保存为 `handoffActor`，且 settlement 完成后仍为当前行动者。

Double 起手的行动号必须 `<= T-1`。若起手为 `T-1`，续手成为行动 `T`，必须先完整提交续手，再触发能力结算。`PASS` 始终提供续手路径；认输或超时仍可立即终止并绕过结算。

Double 标记保留到能力结算供 UI 和审计使用；如果棋子先被提，事件仍留在账本。结算处理 Double 事件时不改变连接或保护，只撤销剩余标记语义并记录无操作轨迹。

### 5.5 阈值与触发

**[FROZEN]**

\[
T(N)=\left\lfloor\frac{150N^2+180}{361}\right\rfloor,
\quad T_9=34,\ T_{13}=70,\ T_{19}=150.
\]

每个已提交落子和 `PASS` 计一次；非法请求和能力结算内部步骤不计数。特殊能力从行动 1 开放。Immortal/Eightway 可在行动 `T` 落下；Double 起手最多为 `T-1`。

每个原子行动完整提交后，按以下条件触发一次能力结算：

1. 新行动数达到 `T`；或
2. 在 `T` 前，新状态形成连续两次 `PASS`。

行动 `T` 的提子、PSK、事件和状态都先提交；若它是特殊落子，它是结算时最新的特殊事件。`T` 前连续两次 `PASS` 触发的是能力结算而非计分。达到 `T` 或完成结算都会清除用于普通终局判断的停着连计。

### 5.6 能力结算闭包

**[FROZEN]** 结算以双方所有已使用特殊事件为输入，使用唯一、稳定、单调的原子事件 ID 建立全局全序；不得使用墙上时间、容器迭代顺序或玩家分组排序。按事件 ID 从新到旧逐个处理：

1. 撤销当前事件的能力；
2. 若 Immortal/Eightway 锚点仍对应原棋子，该棋子保留但成为普通棋子；若已被提，则为审计无操作；Double 机械上为无操作；
3. 重建全盘混合连接、气和保护；
4. 同时删除双方所有零气且未受保护的组；
5. 重建，并防御性重复第 4 步直到固定点；
6. 将该事件完成能力停用、重建和提子后的稳定黑白占据追加到 occupancy-only PSK 历史；能力停用、重建或提子过程中的不稳定中间棋盘不得写入 PSK；
7. 记录完整、有序、确定性的轨迹步骤，然后处理下一个事件。

闭包终止性来自有限事件数和每轮删除严格减少棋子数。实现仍必须有一致性断言，不能靠任意轮数截断。

能力结算不进行 PSK 合法性拒绝。结算生成的占据即使与旧历史重复也允许，仍追加历史，并约束未来玩家落子。结算对搜索表现为触发行动后的一个原子后继状态；撤销、重建和删除步骤不产生 MCTS 节点。

结算完成后：

- 所有特殊能力和未用配额失效；
- 留在棋盘上的棋子均按普通棋子处理；
- PSK 历史完整保留；
- 停着连计重置；
- 只允许普通落子与 `PASS`。

## 6. 普通阶段与终局

**[FROZEN]** 能力结算后的对局遵循普通围棋行动、中国式数子法和同一条完整位置超级劫历史。玩家必须在结算后重新形成连续两次 `PASS` 才进入计分。黑白占地与棋子按面积计分，白贴目 7.5；提子数不另加分。

人类死子同意可以直接形成计分局面；有争议则恢复普通对局。死子提议、双方确认、恢复时行动者/停着/时钟的精确协议为 **[UNFROZEN]**，但它不得由客户端单方面决定。认输和超时立即判负，不执行能力结算，也不生成数目结果。

## 7. 位置超级劫

### 7.1 语义投影

**[FROZEN]** `PositionalSuperkoKey` 只表示每个有效点的黑/白/空占据。它明确排除：

- 当前行动者；
- Immortal/Double/Eightway 标记和棋子来源；
- 配额、行动数、停着数；
- Double 待续手和阶段；
- 终局协商状态。

每次点行动在提子和己方存活检查完成后、提交前检查最终占据。`PASS` 豁免 PSK 重复拒绝检查，但其已接受动作事件仍把未改变的稳定占据追加到历史。官方 Collapse Go 的 PSK 只比较黑白占据，不包含下一手玩家。所有已提交规则事件达到稳定后状态时，其稳定占据都进入完整历史；结算按全局从新到旧逐个处理特殊事件，并在每个事件的能力停用、重建与提子到达稳定闭包后追加一次占据。重建或提子过程中的不稳定中间棋盘绝不进入 PSK。历史跨结算和结算后普通对局持续存在。

结算生成重复允许但不从历史删除，因此它会使未来返回该占据的玩家落子非法。PSK 哈希只是查找加速；哈希碰撞不能改变语义相等性。

### 7.2 起始历史

初始空棋盘在 PSK 语义中的播种和序列化方式必须由规范化描述符明确。该细节当前为 **[UNFROZEN]**；在冻结前不得生成最终规则哈希或宣称跨实现一致。

## 8. 事件日志与重放

### 8.1 权威事件

**[FROZEN]** 只有 C++ 可以产生已接受的游戏事件。逻辑事件至少能表达：

- 规则身份、游戏/会话身份和稳定顺序；
- 提交者、行动者和语义行动；
- 接受行动所依据的前置状态；
- 行动后的权威状态摘要；
- 能力结算触发原因和完整有序轨迹；
- 终局类型、胜者和计分结果；
- 重放完整性所需的版本信息。

精确 JSON 字段、整数宽度、摘要算法和帧格式为 **[UNFROZEN]**。字段未冻结不改变以下边界：Node 不得重写 C++ 事件；客户端状态必须来源于事件或 C++ 快照；日志必须足以通过 C++ 确定性重放。

被拒命令不是游戏状态事件；可以进入独立运维审计流，但不能改变权威事件序列。搜索更新、思考时间统计和 UI 动画进度是观察数据，不是游戏事件。

### 8.2 能力结算轨迹

能力结算仍是触发行动的原子游戏转换，但日志必须携带或引用完整有序轨迹，至少区分：事件能力撤销、无操作原因、同时删除集合、闭包轮次和每个特殊事件后的稳定占据。

搜索只消费最终状态；UI 可以按轨迹动画。关闭轨迹收集不得改变最终状态。为了可维护性，生产实现宜由同一 reducer 在一次执行中同时产生最终状态和轨迹，而不是由前端根据前后盘面猜测。

### 8.3 快照与恢复

**[FROZEN]** 快照是可丢弃索引，不是权威记录。快照必须绑定精确规则身份和日志位置；恢复时 C++ 从可信日志位置重放并验证。Node 不得用 JavaScript 重建规则状态，也不得在 C++ 崩溃后“补算”遗漏事件。

对持久会话，外部确认顺序必须保证不会出现“客户端已收到成功，但崩溃后日志无法重放该成功”的状态。采用数据库事务、预写日志还是其他机制为 **[UNFROZEN]**。

### 8.4 扩展 SGF

**[FROZEN]** 扩展 SGF 仅用于互换。根节点必须携带完整规则身份；自定义属性必须能区分四种落子、Double 续手和能力结算相关信息。标准 `B[]/W[]` 可以作为普通围棋查看器的有损视图，但不能独自恢复配额、标记、阶段、事件顺序或结算轨迹。

SGF 导入必须转换为语义命令并由 C++ 重放/验证；不能绕过 reducer 宽容写盘。具体属性名与兼容策略为 **[UNFROZEN]**。

## 9. 键空间与缓存边界

**[FROZEN]** 下列键用途不同，不得复用名称或相等性假设：

| 键/身份 | 必须表示 | 明确不表示 |
|---|---|---|
| `RulesetIdentity` | 当前显式未分配状态；正式分配后为 `rulesetId + semanticVersion + descriptor SHA-256` | 某一盘游戏状态、模型或代码提交 |
| `PositionalSuperkoKey` | 仅黑白占据 | 行动者、标记、配额、阶段、事件和模型 |
| `SearchKey` | 所有影响未来合法行动、确定性转换和终局的状态，含精确 PSK 上下文 | 公共规则身份的替代品或仅当前盘面 |
| `NNCacheKey` | 模型身份、Model/Input/Action 版本、实际编码输入、对称/集成和影响推理的参数 | 精确 PSK 合法性或搜索转置身份 |
| 协议状态摘要 | 某一事件位置的完整性/重同步依据 | PSK、搜索或 NN 缓存语义 |

### 9.1 搜索键

搜索键至少覆盖：规则身份、占据、当前存活锚点和来源、行动者、阶段、Double 上下文、配额、行动数、停着、特殊事件账本、终局状态和完整 PSK 上下文。两个盘面相同但历史不同的状态可能有不同合法行动，不能合并。

若为了性能使用摘要或增量哈希，必须保留碰撞安全的语义确认，或在无法证明历史相等时禁止转置。上游 GraphHash 的有界重复防护不等于 Collapse Go 的完整历史身份。

### 9.2 NN 缓存键

网络不拥有精确 PSK。推荐缓存未应用合法掩码的原始网络输出：键绑定模型文件身份、Model V19、Inputs V9、Action Schema V1、实际输入张量、对称和推理参数，命中后再由 C++ 应用当前精确掩码。若实现缓存已掩码或已归一化策略，则完整合法掩码也必须进入缓存键。

采用哪种缓存层级及精确字节编码为 **[UNFROZEN]**，但 NN 缓存键不得替代搜索键或 PSK 键。

## 10. 搜索与神经网络边界

### 10.1 行动 ABI

**[FROZEN]** Action Schema V1 在固定 19×19 画布上采用 kind-major 整数 codec。令 `k=0,1,2,3` 分别表示 `NORMAL`、`IMMORTAL`、`DOUBLE_START`、`EIGHTWAY`，令画布点索引 `p∈[0,360]`，则：

`a = 361*k + p`

| 动作族 | 固定 ID 区间 |
|---|---:|
| `NORMAL` | `0..360` |
| `IMMORTAL` | `361..721` |
| `DOUBLE_START` | `722..1082` |
| `EIGHTWAY` | `1083..1443` |
| `PASS` | `1444` |

合计 1445 个槽位，`PASS` 在 D4 下不动。9×9、13×13、19×19 的画布偏移分别为 `(5,5)`、`(3,3)`、`(0,0)`；D4 围绕 `(9,9)`，较小棋盘外的槽位必须被掩码。精确 `p(X,Y)=19Y+X`、语义棋盘转换和 D4 规则见[04-输入特征ABI-V9.md](04-输入特征ABI-V9.md)。JSON 字段名与线协议坐标表示仍为 **[UNFROZEN]**，但不得改变上述整数 codec。

### 10.2 合法掩码

**[FROZEN]** 1445 位掩码由 C++ reducer 精确产生，涵盖：

- 画布外与实际棋盘外点；
- 点位占据；
- 阶段和当前行动者；
- 配额与特殊时间窗；
- Double 强制续手；
- 混合连接、提子、自杀和 Immortal 保护；
- 最终占据 PSK；
- 终局状态。

搜索、训练、网关和客户端只能消费掩码，不得自行近似。非法槽位在策略归一化、根噪声、采样和损失计算中的处理必须由 Action/Training Schema 一致规定。

### 10.3 Double 与备份符号

**[FROZEN]** `DOUBLE_START` 和续手是两个 MCTS 决策节点，第一条边后行动者保持不变。续手节点只展开 `NORMAL/PASS`。若续手触发能力结算，结算闭包包含在该边后继状态内，没有额外选择节点。

网络价值相对节点当前玩家。叶节点只转换一次为 KataGo 白方为正的 `Q`：当前玩家为白则保持，当前玩家为黑则取反。树内不按深度翻号；白方最大化 `Q`，黑方最大化 `-Q`。这使相邻两个同一行动者的 Double 节点保持正确符号。

### 10.4 模型接口

**[FROZEN]** 一个条件模型覆盖普通围棋 `0-0-0` 和 Collapse 变体。固定目标为：

- Model V19；
- Inputs V9，恰好 38 个空间特征、67 个全局特征；
- Training Schema V1；
- Action Schema V1；
- 保留上游 22 个空间和 19 个全局索引，显式保留 `G18`；
- 保留 policy、value、score belief、ownership；
- 新增结算后占据、棋子存活、特殊事件存活三个辅助目标。

精确 Inputs V9 索引、Action Schema 布局、合法掩码、Training Schema 数组和迁移不变量已经由[04-输入特征ABI-V9.md](04-输入特征ABI-V9.md)冻结。当前状态是 **FROZEN DESIGN / NOT YET IMPLEMENTED**；实现不得先行猜测或改写该 ABI。donor 的逐张量来源映射和各后端实现兼容证明仍为 **[AUDIT-BLOCKED]**。精确 PSK 始终留在环境，即使网络输入包含历史摘要。

主干目标是残差/嵌套瓶颈 CNN 加周期性全盘 Transformer、D4-orbit 相对偏置、KataGo 式 global-pooling bias、D4 增广/一致性和可选 8 路推理集成。Debug/Base/Large 分别为 `C96/4 CNN macro/2 Transformer/attn64/4 heads`、`C256/10/4/128/4`、`C384/12/5/192/6`。具体块内实现和损失权重为 **[UNFROZEN]**。

## 11. 协议组件

精确消息名和 JSON 字段为 **[UNFROZEN]**，但逻辑协议必须覆盖下列组件：

1. **能力协商**：协议、规则、Action/Training/Model/Input 版本以及可用模型；
2. **会话创建/加载**：绑定完整规则身份，禁止“最接近规则”替换；
3. **行动提交**：携带幂等命令身份和所依据的权威状态位置；
4. **接受/拒绝**：C++ 产生语义结果；拒绝不改变状态；
5. **权威状态与合法掩码**：快照或可验证增量，始终由 C++ 给出；
6. **能力结算轨迹**：与触发事件绑定的完整有序生成信息；
7. **分析/取消/更新**：结果绑定 basis state、模型身份和搜索配置；
8. **恢复/重同步**：客户端或网关从已知事件位置请求权威状态；
9. **健康与背压**：进程状态、队列限制、超时和可取消性。

Node 可以校验信封形状、大小和版本，但 C++ 必须再次校验不可信输入及语义。未知规则身份、模式版本或关键字段必须失败关闭。响应可在兼容政策允许时接受新增非关键字段，但不得忽略改变语义的未知字段。

## 12. 端到端数据流

### 12.1 玩家行动

**[FROZEN]**

1. React 根据 C++ 掩码显示可选项，发送语义行动意图和其依据的权威状态位置；
2. Node 校验信封、会话和资源限制，不判断行动是否合法；
3. Node 将命令送入负责该会话的 C++ 进程；
4. C++ 使用 `VariantReducer` 验证并事务执行；
5. 若拒绝，C++ 返回原因和未改变的权威位置；
6. 若接受，C++ 产生事件、下一状态、合法掩码及可选结算轨迹；
7. Node 按崩溃一致的顺序持久化并广播，不修改事件语义；
8. React 只应用权威事件/状态；本地待确认显示在接受或拒绝后消失；
9. 若消息丢失或版本不连续，客户端请求重同步，不自行补算。

### 12.2 搜索与分析

1. C++ 从某一精确 `GameState` 建立搜索；
2. 每条边通过同一 reducer 产生后继状态和行动者；
3. C++ 构造 Inputs V9、查询 NN 缓存/模型并应用精确掩码；
4. 叶值一次转换为白方为正，搜索按节点行动者选择；
5. 分析更新绑定 basis state、模型和搜索配置；
6. Node 只路由和取消，React 只显示；basis 已过期的结果不得进入权威状态。

### 12.3 崩溃恢复

1. Node 启动新的 C++ 进程；
2. 选择与日志规则身份一致的可验证快照，或从初始状态开始；
3. 将后续 JSON 事件交给 C++ 重放；
4. C++ 验证事件顺序、语义和状态摘要；
5. 验证完成后才恢复会话服务；
6. 任一不一致均使会话进入显式故障状态，Node 不得修复盘面。

### 12.4 训练数据

1. C++ 自对弈使用生产 reducer、精确掩码和搜索；
2. C++ 按 Training Schema V1 生成权威特征和目标；
3. Python 训练器验证版本和形状后消费；
4. Python oracle 独立用于差分，不成为高性能数据生成器；
5. 在早期一百万行动零差异规则硬闸门通过前，不得启动生产性训练数据生成；为规则测试产生的临时轨迹必须隔离且不得进入训练池；
6. 规则闸门通过后，生产者仍须通过 Inputs/Action/Training ABI、回放/自对弈、导出/推理和确定性恢复的后续生产/训练准入，数据才可进入正式训练池。

## 13. 网关边界

**[FROZEN]** `services/gateway/` 的长期职责包括：

- 启停和监督 C++ 子进程；
- 将一个会话串行路由到其权威引擎上下文；
- 处理幂等、过期命令、取消、超时、限流和背压；
- 持久化 C++ 事件字节及其协议元数据；
- 管理 WebSocket 订阅、重连和重同步；
- 暴露健康、能力和静态资源入口。

它不得：

- 根据前后棋盘差异推导提子或结算；
- 根据客户端声称修改行动者、配额或计数；
- 为兼容旧客户端改写语义行动；
- 在 C++ 不可用时用 JavaScript 继续对局；
- 把搜索建议写成已发生事件。

进程间采用标准输入输出、Unix socket 或其他传输为 **[UNFROZEN]**。无论选择何种传输，诊断通道必须与机器可读协议分离，并设置消息大小、队列和超时上限。

## 14. 客户端边界

**[FROZEN]** `apps/web/` 可以：

- 将画布坐标映射为 Action Schema 定义的点位；
- 根据权威 1445 位掩码启用、禁用和解释动作；
- 显示配额、行动数、阶段、Double 待续手和当前行动者；
- 按 C++ 轨迹播放能力撤销与棋子删除动画；
- 显示带 basis 的分析结果；
- 保存非权威 UI 偏好和暂存意图。

客户端不得：

- 用 flood fill、局部气计算或本地规则库决定提子；
- 计算 PSK、阈值触发、能力结算、终局或面积得分；
- 从动画结束状态反推权威棋盘；
- 在离线状态下产生可合并的游戏事件；
- 把扩展 SGF 直接当作可信状态导入。

## 15. 分层一致性与安全闸门

### 15.1 早期规则差分硬闸门

**[FROZEN]** 该门槛必须位于搜索、协议、网关、客户端和训练数据生产之前，至少包括：

- 至少一百万个随机合法/非法原子行动的 C++/Python 零个可复现差异；
- Immortal、Eightway、Double、阈值、全局逆序结算、无操作账本和 settlement 生成重复的黄金夹具；
- ASan/UBSan、make/undo/redo 或等价回滚；
- D4 对状态、动作、掩码、PSK 历史和结算轨迹的一致变换；
- occupancy-only PSK 跨结算和普通阶段，并验证每个事件稳定闭包进入历史、不稳定中间盘不进入历史。

该门槛证明的是 Python/C++ reducer 的规则一致性，不是生产或训练就绪声明。

### 15.2 后续生产者与训练准入

**[FROZEN]** 在规则门槛之后，还必须独立验证：

- 搜索使用 kind-major typed actions、显式行动者和事务式 settlement，不按 ply 奇偶翻号；
- C++ 特征生成、Python 训练加载、模型导出与至少一个生产推理后端逐项符合 Model V19、Inputs V9、Training Schema V1 和 Action Schema V1；
- 回放与自对弈生产者绑定精确规则身份状态、合法掩码、PSK 上下文、模型/checkpoint 与 Schema 版本，并可确定性重放；
- JSON 日志、快照验证、进程崩溃恢复、WebSocket 丢包/乱序/重连、背压和过期分析均通过端到端测试。

本门槛通过前，规则闸门之后产生的试验数据仍须隔离，不得进入正式训练池，也不得宣称系统已达到生产或训练就绪。

### 15.3 Beta 与发行准入

**[FROZEN]** Beta/发行还必须验证跨版本拒绝与迁移、长局 PSK、负载与资源上限、许可证和第三方声明，以及 SGF 导入必须经 C++ 验证、导入/导出的声明能力与实际损失模型一致。

任何线上规则差异都不能用模型强度、搜索访问量、UI 修正或事件后处理掩盖。

## 16. 显式未决与审计阻塞

### UNFROZEN

- 持久化、确认事务、快照格式、认证、部署和扩缩容；
- 扩展 SGF 属性；
- 死子协商、争议恢复、时钟和公共 undo/branch 协议；

- 模型块内细节、辅助头张量和损失权重。

## English Summary

C++ is the sole production authority for rules, search transitions, terminal state, scoring, authoritative events, and replay. Python contains an independently implemented slow differential oracle; training code is also non-authoritative. The Node gateway only supervises processes and sessions, validates envelopes, orchestrates persistence and WebSockets, and enforces operational limits. The React/TypeScript client only renders C++ state, legal masks, analysis, and settlement traces.

`GameState` is an indivisible aggregate containing rules identity, occupancy, stable stone provenance and special markers, actor and phase, global action count, pass streak, quotas, pending Double context, the global special-event ledger, exact positional-superko history, and terminal/scoring state. Stable provenance is required so that reoccupying a captured anchor point cannot revive an old ability.

`VariantReducer` is the only production transition path. A rejected command has zero side effects. A placement transaction stages the stone and ability, rebuilds mixed groups, simultaneously removes all opponent zero-liberty unprotected groups, rebuilds, verifies the new own group has a liberty or Immortal protection, checks occupancy-only PSK, and then commits every state field atomically.

Double-Move creates two real MCTS decisions. The legal start consumes the quota and leaves the same actor in a continuation phase where only Normal or Pass is legal. A Normal continuation independently performs placement, capture, survival, and PSK checks. A Pass continuation performs none of those board-legality operations, but still updates the action and pass counters, emits an event, clears pending Double, and appends the unchanged stable occupancy. After either legal continuation commits, the next actor is deterministically the continuation actor’s opponent; if settlement follows, that opponent is retained as `handoffActor`. Settlement is a deterministic reducer closure, not a search phase.

Settlement processes all used special events across both players in one global newest-to-oldest order. It deactivates one event at a time, rebuilds the whole board, simultaneously removes every zero-liberty unprotected group of either color, repeats to closure, appends that event's stable black/white occupancy to PSK history, and emits a complete ordered trace. Unstable rebuild/capture intermediates are never PSK history states. Captured events and Double events remain auditable no-ops. Settlement-generated repeats are allowed but constrain future player moves.

The JSON event log is authoritative. Snapshots are disposable indexes, and extended SGF is interchange only. Recovery replays the JSON log through C++; Node and the browser never reconstruct rules. Accepted events come only from C++, while rejected commands and analysis updates are not game-state events.

Ruleset identity, positional-superko key, search key, and neural-cache key are separate. The final public `rulesetId` literal and canonical-descriptor encoding/canonicalization are **UNFROZEN / unassigned**; the final public descriptor SHA-256 is **AUDIT-BLOCKED / unassigned**. `collapse-go` is only a repository slug and candidate name. Official Collapse Go PSK contains black/white occupancy only and excludes the next actor. The search key contains every future-relevant field, including exact repetition context. The NN cache key binds model/checkpoint identity, schema versions, encoded inputs, and inference parameters; exact legality remains in the C++ mask.

The model uses a fixed 19×19 canvas and exactly 1445 kind-major action IDs: NORMAL 0–360, IMMORTAL 361–721, DOUBLE_START 722–1082, EIGHTWAY 1083–1443, and PASS 1444. Smaller boards are centered at offsets `(5,5)` and `(3,3)`, D4 acts around `(9,9)`, and Pass is invariant. Network values are current-player-relative and are converted once at the leaf to white-positive `Q`; White maximizes `Q`, Black maximizes `-Q`, with no depth-parity sign flips.

The one-million-action zero-difference rule gate is an early prerequisite for search, protocol, gateway, client, and training-data production. It is separate from the later production/training-readiness gate for exact ABI implementation, replay and self-play producers, model export/inference, deterministic recovery, and formal training-pool admission.

Exact protocol fields, canonical descriptor fields/bytes, SGF properties, persistence technology, dead-stone wire flow, model microarchitecture, and donor tensor maps remain explicitly unfrozen or audit-blocked. Inputs V9 and the Action Schema V1 integer codec are already frozen in [04-输入特征ABI-V9.md](04-输入特征ABI-V9.md). No source implementation belongs in the first documentation commit.
